| 候选 | 决定 | 主要依据 |
|---|---|---|
| A-core | 拒绝 | 大块切分能增加压力成功数，但目标共同工作明显变慢；N5 有 +40.43% used_end 反例 |
| B-core | 拒绝 | 高地址尾分配通过尾增长和前缀占用检查，仍继承 A 的非尾布局反例与耗时成本 |
| A-wire | 拒绝 | 目标碎片空间改善，但 N5 有 +52.03% used_end 反例 |
| B-wire | 拒绝 | 严格扣除公布预算；局部多完成 3 次压力请求，仍有相同 +52.03% 反例 |
| C-linear | 拒绝本实现 | 批量头部复用约快 20 倍，但长链尾命中/无适配项约慢 7 倍；没有 arena 空间收益 |
| C-index | 拒绝本实现 | 不改变 donor；部分查找很快，但实际宿主容量超过预登记 `4×F+4096` 预算，同桶对齐拒绝仍慢 |
| selected 组合 | 条件不成立 | 没有独立通过筛选的组成部分，不组合失败候选 |
| D-batch | 条件不成立 | 未满足“先有独立通过的基线”门槛；不据此宣称 F 没有可合并的碎片 |

## 实现和验证方法

`tools/stage3_candidates_{core,wire,index}.py` 从冻结的 F 生成独立头副本，
每处源码锚点必须恰好匹配一次。生产头没有试验开关或诊断接口。
每一批次内的所有变体从同一次冻结的 tests/tools/generator 输入生成。正式计时为 v2，
补强后的模型和诊断为 v3；二者的候选运行期双头哈希相同，计时二进制没有重建。
转换脚本、源文件、编译命令、
二进制及工具身份均可追溯。

A-core 非尾切分把新头前的对齐余量归入前块，残余占 donor 原槽位；物理尾 donor 整块复用。
B-core 只另改尾 donor，从高地址分配，前缀保留原头、原对齐和槽位。
每个 Core 残块至少有 1 字节用户区和独立 16 字节头。
A/B-wire 保持原尺寸类和链表 donor 顺序，残块插入对应类头，至少公布 8 字节。
隐藏物理后缀有明确归属，但不扩大公布预算；B-wire 按 `W−R−16−P` 扣除请求、头和尾部余量，
再受前缀物理容量和原公布边界限制。不把隐藏余量恢复归为纯切分收益。
这些切分准备不需要宿主分配；不虚构 split 专属的 fail-after-N 分配点。

C-linear 用稳定槽位、活动 FIFO 和空洞链代替 vector 的中间删除；C-index 在相同槽位上增加
32 个尺寸桶、非空位图及顺序号。它跨所有合格桶比较最早 donor，保持 Core 的尺寸、
存储对齐和实际地址条件；检测到遍历中的坏引用或顺序异常时完整线性后备；诊断另检查缺失的位图/桶引用。最坏查找仍为线性，位图不是无条件 O(1)。
定向测试检查跨桶顺序、同桶大小/对齐、无适配项、空洞重用、move/swap/prune、load 后懒建，
并通过仅存在于生成诊断头的入口注入最大序号及坏槽位引用。

参考模型只知道物理区间、拥有者、有效数据和明确允许的损失，不复制 allocator 选块算法。
它逐操作验证存活字节、实际对齐、不重叠、Core/wire 唯一拥有、头部、链表/索引可达及计数。
覆盖账本保留前一步已知的物理范围，能抓住“残块记录和计数同时消失”的情况；未知对齐间隙
从不并入已知范围。C 另用外部 FIFO 逐请求核对 donor，基址相同，没有跨映射的超页余数干扰。

新增常规测试 `test_allocator_model`、`test_allocator_failures` 已进入 CMake 和 sanitizer 清单。
生产头的常规 smoke 检查存活数据；完整空闲表拥有权、索引和覆盖账本使用生成诊断头验证，不公开私有测试接口。
后者只在被测操作周围开启真实 global-new fail-after-N，覆盖 Core 回收、wire→Core 转移
和 load 后首次元数据建立，分别验证安全和损失容量。既有 `noexcept` 尽力回收契约不变。

F 的具体位置断言仍保留。B-core 的既有 policy 测试副本改用明确的高地址策略预期，
同时检查容量未增长、结果在原 donor 内、物理尾部、头部和对齐；不是删除失败断言。

## 时间、空间和宿主成本

平台为本机 Apple M3 Pro / 36 GiB / macOS arm64 / 16 KiB 页，固定 P2996 Clang
`d77eff1cbd78fd065668acf93b1f5f400d39134d` 和显式 MacOSX26.5 SDK。
正式计时与诊断二进制分开，由本会话串行调度；计时期间没有本会话的 C++ 构建或另一基准。

先做同二进制 F/F 的 60 个查找条件和 5 个默认锚点 A/A，然后锁定原采用预算。
A/A 的 64 KiB load 配对中位比为 0.9437，单对范围 0.8064–1.0739，不能分辨 2% 级默认回退。
没有根据候选数据放宽门槛。

正式数据包括 F 对六候选、B 对对应 A，以及 A/A；每条件 1 对预热、8 对正式测量，
AB/BA 各 4 对。它们是桌面上的协调筛选窗口，不是三个独立安静确认窗口。
六候选在筛选阶段已有明确反例/成本，因此没有进入采用确认，也没有把连续运行虚报为独立确认。
正式筛选档案共 32 个窗口、983 个条件、17,694 条样本，其中正式测量 15,728 条、预热 1,966 条。
另有 777 条独立诊断记录，按变体与输入条件核对其中微型、碎片和 N5 轨迹的 17,064 条相关计时样本，
其中正式测量 15,168 条、预热 1,896 条。其余 630 条默认锚点记录不属于这套分配器计数器矩阵。
区间、执行顺序分层和完整配对分布保存在原始审计摘要；min/max 顺序统计区间的覆盖解释
以样本独立为前提，不用于宣称已证明 2% 等价或估计 p99。

共同碎片负载的布局和压力结果如下。压力成功数单列，压力耗时不进入共同工作时间。

| 工作负载 | F used_end | 切分 used_end | F 压力成功数 | 切分压力成功数 |
|---|---:|---:|---:|---:|
| Core 大块→小块，A-core/B-core | 6,701,232 | 4,292,784 | 2,630 | 5,561 |
| wire 大块→小块，A-wire | 6,832,400 | 4,423,952 | 2,504 | 5,432 |
| wire 大块→小块，B-wire | 6,832,400 | 4,423,952 | 2,504 | 5,435 |

A-core 的共同耗时配对 F/A 中位数约 0.609；第一窗总体中位耗时约 0.388→0.647 ms。
这是超过预登记 5% 空间目标耗时预算的反例。wire 目标负载的共同耗时较接近，但不能
抵消下面的精确布局反例。共同有效数据不变，不能把更多压力工作用作提速证据。
表中 used_end 不是逻辑长度、可访问页或 RSS；压力后的 wire 长度也不是共同工作阶段的长度。

16 条 N5 轨迹 × 预分配/Explicit/Automatic 共 48 条相同操作轨迹，所有最终逻辑值和 wire 往返检查一致。
Core A/B 在 `64 KiB / cadence=256 / burst=1 / 持续存活 / Automatic` 中，used_end
从 4,515,392 增至 6,341,168（+40.43%）。wire A/B 在相同轴的 Explicit 中，
从 4,235,792 增至 6,439,856（+52.03%）。不同轨迹也有改善，但没有解决这些反例。
尾 donor 保护避免一种尾身份丢失，并不能使非尾切分顺序普遍更紧凑。

C 使用完全相同 donor 和最终布局，不能宣称有 arena 空间收益。
4096 项条件下，C-linear 的批量 head/dense 配对 F/C 比约 19.4–20.3；
tail 和持续无适配项约 0.131–0.146，分别约慢 6.8–7.6 倍。
C-index 的部分跨桶查找很快，仍须支付同桶对齐拒绝及维护成本。
宿主成本必须包含保留的空洞槽位、实际 vector capacity 和固定桶数组，不能只数有效记录。
在相同 4096 项 head 条件下，F 为 65,560 B，C-linear 为 229,440 B，
C-index 为 295,496 B；后者超过 `4×65,560+4096=266,336 B` 的预算。
对齐拒绝条件还会保留更多槽位，不能用已失活条目数减少这项容量成本。

诊断扫描是 eligibility predicate 次数，不包含全部位图遍历/顺序比较；元数据移动字节是
已插桩的 vector erase 移动，未覆盖 vector 扩容搬运；向量迁移字节仅覆盖指定 XVector reserve
路径，不是 string/进程总复制量。最大 owner 元数据容量是成功 Core 回收后采样的单个 owner 值；没有发生成功回收时的 0 表示未采样，
不能解释为零固定对象成本，也不是并存 owner 的总宿主峰值。微型负载的直接容量探针包含固定桶数组。
这些诊断覆盖初始化、工作及保存/加载验证，不仅是计时循环；RSS 是单独的进程观测。N3 更完整归因仍未完成。

## 最终验收和证据

最终正常随机模型完成 800,000 次操作，深度模型完成 32,000,000 次操作。
正常为 8 个种子各 10,000 次，深度为 32 个种子各 100,000 次；七个 Core 变体和三个 wire 变体分别运行，
每一步仍检查全部当前区间、有效数据和覆盖守恒，没有降低深度轨迹的验证频率。
冻结的 32×100,000 个随机输入字也通过独立重放核对。
物理地址排序改为独立的稳定槽位与地址索引，以免每一步重新排序；它不使用 allocator donor 规则。
每个变体覆盖 17 个实际宿主分配故障点，模型运行 10 个负向控制。
候选相关的六份正确性记录共 65 条命令，另有 31 条补充功能运行：28 条顺序/交错容器及显式池条件，
3 条守卫。实际基址不满足两倍运行时页对齐的定向检查也已覆盖七个变体。
