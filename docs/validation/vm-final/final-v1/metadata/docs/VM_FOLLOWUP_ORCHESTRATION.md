## 执行资源与顺序

W4 首先实现并验证 `experiments/vm_coordination/run_job.py`：

```text
run_job.py status

  --out NEW_EVIDENCE_DIR --timeout-seconds N -- COMMAND ARG...
```

当前本机使用操作系统互斥锁，稳定锁文件位于 `build/vm-coordination/`，不删除/替换锁文件。
锁覆盖被执行命令整个进程树的生命周期；不能仅用 JSON 到期时间解锁正在运行的工作。
超时、取消、异常必须记录，等待自有子进程终止/回收后再释放锁；不得误杀其他会话或
用户进程。默认有界等待，繁忙时返回可识别的 busy 状态，不标通过。保留排他创建的
日志、命令、返回码、owner、开始/结束时间和结果清单；离线检查不执行被测命令。
先以轻量进程验证互斥、超时、失败、孤儿/子进程回收、既有输出保护，再发布 ready 状态。

网络矩阵、sanitizer、压力测试或基准。之后这些操作均通过它执行。每个编译任务使用

## W1：网络功能与共享契约

第一版实验选择本机 TCP 回环、复用一条连接、单个在途请求；仅决定参考实验条件，
不替用户选定生产协议/网络库。使用既有 V1 header/used_bytes 定界，不增加网络报文
字段、长度前缀、稀疏或分段协议。先有界接收 owning string，再 verified load、处理、
verified save 和持有 owning string 的完整发送。输入语义复用文件参考的确定性 schema。

先实现可注入的传输进度/取消/资源状态模型，再接真实回环。连接与每次操作均有明确
截止时间；拒绝忙循环。半帧失败终止实验自有连接，不重发整帧或猜测重同步。单帧上限、
owner 容量、在途总字节、队列限额分别计数。缓冲持有到操作真正完成，取消请求不能
被当作已完成；一次操作只终结一次。模拟异步生命周期与真实适配器验证分别标注。

W1 的第一项小交付是 `experiments/vm_network/contract.json` 与 HANDOFF，供 W3 并行
实现运行器。至少冻结：schema/version、CLI、参数范围、pool 模式、timing/diagnostic
编译开关、JSON 字段/单位、测试 case ID、错误退出码及计时排除项。推荐 CLI：

```text
net_reference fixture --output NEW_FILE --elements N
net_reference smoke --out-dir NEW_DIR
net_reference run --input FILE --out-dir NEW_DIR --pool none|cold|warm
  --iterations N --max-wire BYTES --owner-capacity BYTES
  --max-inflight-bytes BYTES --timeout-ms N
```

具体字段由 W1 提出并经统筹确认后锁定，W3 不得猜测未发布接口。主指标采用客户端
完整请求/响应且响应 verified 校验完成的耗时；发送完成、服务端处理和分段成本另列。
连接建立、准备/预热/清池、析构和核验边界必须明确。整体计时构建移除逐阶段时钟。

测试按网络方案覆盖 header 所有切分点、预登记 payload 边界、连续多帧、长度溢出、
坏头/坏图、短读写/暂不可用/零进度、取消/迟到完成/断连、慢读背压和三种池模式。
精确列出预期 case ID，不能以任意异常视为负例通过。成功路径逐值核对；资源和发送
缓冲寿命有可验证计数/断言。W1 完成功能后冻结源码与双构建，不自行运行性能矩阵。
