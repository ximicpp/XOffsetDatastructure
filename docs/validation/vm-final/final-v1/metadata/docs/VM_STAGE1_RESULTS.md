# 下一阶段首批实施：构建、验证与测量基础

日期：2026-10-15。工作分支：`next_cpp26`。本批落实
[开发计划](VM_NEXT_STAGE_PLAN.md) 的 N0、N1 本地可验证部分与 N3 测量基础。
后续池/Automatic、消费端打包和分配器实验尚未开始，不将整份路线图标记完成。

## 实施结果

### 构建与验证

- Linux 完整 CI 改为读取已实际拉取验证的镜像摘要；编译器、Boost、TypeLayout
  通过 [固定输入清单](../toolchains/vm-validation.json) 与检查脚本校验。
  Docker 源码构建配方固定 compiler commit；它的 Ubuntu/apt 输入仍可变，因此不能
  把源码重建配方称作已经验证的同一镜像，CI 使用固定 digest。
- `XOFFSET_STORAGE_ONLY=ON` 在反射及第三方依赖配置之前分流，普通 C++17 编译器
  可以独立构建 OS 存储和池。完整库进行实际反射、展开、拼接、XBuffer 编译及链接检查。
- 原负编译测试文件缺失，之前的条件检查实际会跳过。本批增加必需的正/反例，
  同时检查预期 static assertion；错误接受或无关编译错误均为失败。
- 自动生成准确清单：36 个测试程序、7 个子进程场景、3 个工具检查，共 46 个 CTest；
  3 个配置阶段编译检查另列。仅 OS 模式为 2 项。
- 完整构建脚本强制退出缓存中的 storage-only 模式；显式编译器无效时不回退，支持
  PATH 中的编译器名称、独立构建目录及显式 macOS SDK。必需签名工具缺失不再跳过。
- CI 日志目录先创建，归档编译检查、实际清单和 CTest 日志；增加 Linux/macOS/Windows
  的独立 OS 层任务及 Python 工具自检。仅修改工作流，未推送或触发远端运行。

### 可移植验证入口

[validate_vm.py](../tools/validate_vm.py) 接受显式源码目录/归档、依赖、运行库及历史
wire 输入包，输出独立目录及源码/依赖/工具链指纹、命令、测试清单和结果。
普通全量验证不要求 sanitizer runtime；已有目录不可覆盖，零测试、跳过、错误清单、
参数覆盖验证模式及前置条件缺失不能报告通过。

Linux sanitizer 资源必须自包含。原历史 `resource/` 的链接指向父目录和容器内路径，
单独挂载会失效；本批保留该失败记录，并使用新目录物化同一 package 的库及固定镜像的
内建头后重验。前置检查现拒绝越界、绝对、断链或循环链接，并完整记录根内链接文件。
MSVC 使用独立 CMake/CI 入口，Python runner 目前只承诺 Clang/GNU 驱动接口。

完整用法见 [验证入口说明](VM_VALIDATION_RUNNER.md)。

### 性能测量基础

增加 A/A 与 D/F 冻结源码测量、独立窗口、配对统计、完整语义/布局校验及数据审计。
三个窗口采集 252 个正式样本和 36 个预热样本，全部保留。

同一 F 二进制的 A/A 已出现与目标差异相当或更大的变化，保存路径 D/F 的方向也不稳定。
另一任务的容器持续运行，安静环境前提未满足；因此本次仅为诊断证据，不能定位此前
约 2–3% 的回退，也不能证明它不存在。没有据此改动实现或放宽采用标准。
详见 [原始结果及限制](perf/2026-10-15-vm-stage1/README.md)。

审查还修正了测量入口的失败恢复问题：新版窗口末尾身份校验通过、样本及汇总写完后
才发布完成状态；失败或中断窗口不可续跑、读取或通过审计。历史三窗未改写，按其冻结
审计器核验；协议区别及复现方式见 [测量入口勘误](VM_STAGE1_RUNNER_ERRATA.md)。
早期 F 元数据残留 E 标签的问题以 [独立勘误](VM_EVIDENCE_ERRATA.md) 解释，历史文件不变。

## 验证证据

最终实际检查及日志见 [验证索引](validation/2026-10-15-vm-stage1/README.md)。
macOS 使用明确的 26.5 SDK；本机默认 SDK 已变为 27.0，不把默认环境视为历史工具链。
Linux 完整库运行于 x86_64 CPU 模拟，独立 GCC 存储检查运行于原生 Linux arm64。
模拟执行只提供功能结论。

独立审查覆盖 CMake、CI/构建入口、验证 runner 和性能采样/恢复协议，发现项已修正并
加入针对性检查。测试数量在证据索引中按最终结果列出，不混用旧 F 的验收记录。
