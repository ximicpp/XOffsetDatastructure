## 1. 结论与优先级

下一阶段先把 F 变成可持续验证、可由外部项目使用的实验性版本，再根据新证据优化性能。
优先级如下：

1. 固定工具链和依赖，消除验证入口的假阳性，使冻结源码能在干净环境复现。
2. 建立独立 OS 层构建和 Windows 原生验证；完善完整库的持续验证与消费端打包。
3. 复核默认路径约 2–3% 的小幅回退，并补足混合容量、并发、随机释放和相同操作轨迹的测量。
4. 分别改善池的成本和 Automatic 的空间代价，只采用有可重复收益的最小变更。
5. 将分配器的查找、切分、尾块身份和合并拆成独立实验；Core 与 wire 分别决策。
6. 直接 I/O、分段保存及外部只读视图进入条件研究，不以新增 API 数量作为完成标准。

F 已解决稳定地址、显式自动增长、页面回收和池化复用的主体问题。当前主要缺口是
可复现性、平台覆盖和负载代表性；尚无证据支持立即换用复杂分配器、默认开池或默认自动回收。

## 2. 基线与证据边界

| 项目 | 已确认事实 | 下一步含义 |
|---|---|---|
| 地址与增长 | 固定最大容量内基址稳定；默认 Explicit，可选 Automatic | 保持硬上限与失败契约；不引入超过上限后搬迁的后门 |
| 容器增长 | 只有存活物理尾块可原地扩展 | arena 基址稳定不等于所有容器元素地址永远稳定 |

## 3. 系统审查

### 3.1 构建、验证和交付

- `.github/workflows/ci.yml` 已有真实 Linux P2996 构建、CTest 和签名检查；
  `ci-test.yml` 另做结构检查。问题是前者使用可变 `:latest` 镜像，Dockerfile 与
  compose 的编译器来源仍可为 `HEAD`，不能稳定对应已经验证的 F 工具链。
- CI 在没有先创建宿主 `build/` 的情况下向 `build/ci-build.log` 写日志，存在
  干净 checkout 启动失败风险。此项来自源码检查，尚非已观察到的远端失败。
- 归档验证依赖本地镜像 ID、历史 `build/` 路径及 sanitizer runtime。
  现有证据可审计，但不能直接等同于任意新机器上的一键复现。
- OS 头和两个存储测试可以使用普通 C++17；顶层 CMake 却先拒绝非 Clang 编译器，
  并无条件配置完整反射目标，阻断真正独立的存储构建。普通 Clang 通过配置不证明
  反射能力可用；测试的 `-UNDEBUG` 也需要按 MSVC/Clang/GCC 区分。
- 多态拒绝的负编译检查把任意编译失败视为成功，意外编译成功却只发 warning。
  缺依赖、坏工具链可能造成假阳性，应加入正例并确认预期诊断。
- 当前没有完整 install/export 消费路径，存在 `CMAKE_SOURCE_DIR` 假设，并总是构建
  examples/tools/tests。新增 OS 头后，也必须验证安装包同时提供两个头和所需依赖。
- `CLAUDE.md` 的测试清单仍是 34 个程序/44 项；当前为 36 个程序、46 项 CTest。
  新清单应从构建产物生成，区分程序数、子进程场景数与工具检查数。

### 3.2 内存、并发和可观测性

- Core 使用首适配整块复用和 `vector` 元数据；wire 使用尺寸类链表。两层拥有权不同，
  空闲块不能同时出现在两层，不能直接把 wire 的空闲字节加作 Core 的可立即使用容量。
- `get_free_memory()` 统计 Core 空闲块和尾部，未包含 wire 缓存；`memory_stats()`
  的 used 是其派生值，不是存活对象有效字节，也不是 RSS。保留旧语义，新增诊断需另命名。
- Core 释放时宿主元数据分配失败会放弃该块的回收。当前保证安全和 `noexcept`，
  不保证宿主 OOM 时可复用容量守恒。池归还/move/swap 无宿主分配，是另一项契约。
- owner 注册已使用同步的精确基址哈希索引。池的精确容量匹配仍有扫描和互斥开销，
  `clear()` 的解除映射在锁内执行。源码说明潜在成本，尚不能证明它们是实测瓶颈。
- 共享池安全不代表同一 XBuffer 的并发修改安全。后续压力测试应让各线程持有独立
  owner，另外明确销毁、外部同步和借出视图的生命周期边界。
- 页权限、Windows commit、RSS 和逻辑长度是不同量。故障注入可验证已返回错误的
  原子性，不能据此承诺所有平台的实际物理内存耗尽都可恢复为 C++ 异常。

### 3.3 原始方向与当前决策的对应

| 原始建议 | 当前/下一阶段处理 |
|---|---|
| 虚拟地址预留、自动增长、尾块扩展 | 已完成主体；继续验证边界和实际成本 |
| O(1) owner 掩码控制页 | 已采用同步精确基址哈希；先测其争用，不增加强对齐地址空间和控制页机制 |
| 小 buffer 使用 vector 退路 | 当前统一 VM 契约；先测显式池，不恢复可能破坏稳定地址预期的隐式后端切换 |
| 最佳适配、切分、合并 | E 已反证直接组合；重新拆分研究，不恢复 E |
| 零复制收发 | 当前仍为拥有数据的复制加载/保存；需要真实输入输出链路、验证与生命周期设计 |
| 默认 shrink 释放物理页 | 保持显式 reclaim；已有再增长代价不支持默认开启 |

## 4. 下一阶段必须保持的契约

1. 存活 owner 的基址不随 grow、shrink 或 reclaim 移动；硬上限明确，失败不悄悄换址。
2. 默认 Explicit、无池、save/shrink 不自动回收；新策略不能暗中改变旧调用行为。
3. 成功准备页面和元数据后再发布分配结果。元素构造失败可能保留已经增加的容量，
   不应把现有保证误写成“所有失败都回滚容量”。
4. V1 wire 格式、校验和规范化语义不变；`reserved0` 保持零，运行期索引不序列化。
5. Core、wire 和 live 块各自唯一所有权；任何新索引只引用对应块，不获得第二份所有权。
6. 池的空闲映射数、预留字节、可访问字节均有上限；存活 owner 不计入空闲预算。
   清池只处理空闲映射；已借出 owner 保持有效，之后仍可归还。
7. 脏区再次暴露前清零或完全覆盖；故障路径不发布不完整状态。运行期策略随 owner
   转移，不通过 wire 传递，compaction 的独立 owner 语义保持现状。
8. 公开指针、span 与容器引用仍受对象生命周期和容器自身扩容影响；稳定 VM 不提供自动同步。

## 5. 工作包与开发设计

### N0 — 可复现基线与验证入口，P0

**文件范围：** `.github/workflows/ci.yml`、Dockerfile、compose/build 脚本、
`tests/CMakeLists.txt`、`CLAUDE.md`；新增受维护的工具链清单和 `tools/` 验证入口。

- 清单记录实际 compiler commit、target、SDK/libc++、sanitizer runtime、Boost、TypeLayout、
  编译参数和源码哈希。可分平台锁定版本，不把不同工具链强行标成同一配置。
- 镜像使用经过拉取验证的 registry digest；本地 image ID 只能作本地证据，不能伪装成
  可移植引用。若无对应镜像，使用锁定源码的构建配方；不默认替换成另一套编译器。
- 受维护入口显式接受源码包、依赖和历史 wire 输入包，解包至独立目录；普通全量验证
  不应无条件依赖 sanitizer runtime。缺少前置条件应明确报错，不能跳过后仍报通过。
- 创建日志目录后启动构建；负编译测试同时验证可编译正例、预期拒绝原因和意外通过失败。
- 新 benchmark 标签由 variant 与源码指纹生成。旧 `accepted_f/followup` 元数据中残留
  E 字样的说明，用新增勘误索引解释，保留原文件和哈希；不改写历史证据。

**验收：** 干净构建目录可复现；故意缺依赖不会通过负编译检查；禁用拒绝条件会被检测；
实际测试清单与报告一致；维护入口不依赖作者的绝对路径或未声明的旧 build 文件。

### N1 — 分层平台验证，P0/P1，依赖 N0

**文件范围：** 顶层/测试 CMake、存储测试、CI 工作流和平台支持表。

设计独立的 storage-only 配置入口，在编译器品牌门禁和完整库依赖配置之前分流；
它只编译 OS 头、池和必要测试。完整库模式增加真实反射编译/链接检查，不能把
“Clang 品牌”当作实际特性通过。

| 验证层 | 目标 | 可作出的结论 |
|---|---|---|
| 独立 C++17 OS 层 | Linux/macOS 普通编译器；Windows 原生 MSVC 或 clang-cl | 平台映射、回收和池实现可用 |
| 完整 P2996 库 | 固定工具链 Linux/macOS；保留 sanitizer、TSan、wire 互通入口 | 对应工具链上的库集成可用 |
| Windows 完整库 | 单独验证可用的 P2996 工具链、依赖和全部集成测试 | 只有通过该层才能宣称 Windows 完整支持 |
| 性能 | macOS 原生及可获得的 Linux 原生设备 | 仅归属于实际设备；模拟执行不提供原生性能结论 |

Windows OS 层检查预留粒度与页大小、提交/撤销提交、重新清零、完整预留释放、
move/swap、池预算、并发 clear 与存活 owner。用户分配的超页对齐属于完整库分配器
验收，不能由 OS 层通过推断。结合 `VirtualQuery` 验证状态，不要用进程 working set
代替 commit 状态。参见官方
[VirtualAlloc](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc) 和
[VirtualFree](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualfree)。

PR 级任务保留确定性的全量/针对性检查；较重的 sanitizer、TSan 和历史 wire 矩阵可以
分作独立任务。故障注入与平台真实系统调用测试并存。资源不足时记录未验证项，不降级为通过。

### N2 — 消费端打包与支持契约，P1，依赖 N0/N1 的构建分层

**文件范围：** CMake、两个公开头、依赖声明、README/迁移文档、新增独立 consumer 示例。

- 提供命名空间化的 CMake interface target、install/export 配置及可关闭的 tests/tools/examples。
  用当前项目路径而非顶层消费项目路径；导出包不能泄漏开发机器的绝对目录。
- 明确 TypeLayout 和 Boost 所需头的来源：首版沿用锁定依赖，选择随包提供或经明确
  dependency target 引入，校验许可证和必需头完整性；不只安装本项目两个头后声称自包含。
- 特殊编译器/标准库定位由明确 toolchain 配置承担，消费 target 传播必要语言特性、
  依赖及 Threads；不把本机 clang 安装路径硬编码进导出包。
- 增加源码树外 `find_package` 消费测试和多翻译单元链接测试，覆盖 owner 注册、池
  与跨翻译单元对象传递；不在本轮无证据宣称动态插件边界也已受支持。
- 发布说明标注实验性工具链、验证平台、已接受代价和未验证平台，不擅自改变 wire 版本。
  上游 [clang-p2996](https://github.com/bloomberg/clang-p2996) 仍明确定位为实验实现，
  因此本阶段交付是可复现的实验性版本，CI 通过不等于生产工具链认证。

**验收：** 独立项目使用安装目录可构建、运行；默认不意外构建本库测试；无源码树路径依赖；
多翻译单元共享状态及销毁顺序正确；支持表区分 OS 层、完整库和性能平台。

### N3 — 测量基础与默认路径归因，P1，依赖 N0

**文件范围：** `tools/bench_vm_*.cpp`、runner、诊断构建开关、新一轮独立证据目录。

先做同版本 A/A 和 D/F 复测：固定编译器、SDK、依赖、输入、初始/最大容量、
计时范围及 CPU 环境；交替或随机配对顺序。把首次 save、重复 save、冷池、暖池分别报告。
小幅差异至少跨三个独立安静运行窗口；稳定复现后才做 D＋单项、F－单项消融。
不要凭一次剖析就将 3% 差异归因于 owner 哈希或某个条件分支。

诊断构建与正式计时构建分开，日志预分配、计时外输出。新增或明确以下测量口径：

- Core/wire 扫描次数、元数据移动/宿主分配次数与峰值、缓存转移、尾块扩展失败原因；
- 真正发生的容器迁移与复制字节、增长事件、重试、系统调用和回收结果；
- used_end、逻辑长度、可访问页、预留地址、Core/wire 空闲、池空闲预算分别计量；
- RSS/working set 单独采样；不把进程值归为单个 arena 的独占占用；
- 多 buffer 的创建/分配/释放吞吐和 owner 索引争用，排除 live 数量与实际工作量混淆。

已有估算的 move 字节或仅覆盖显式 grow 的计数不得改名为精确总数。实际数据引用计数
必须有定义；小批次平均值不能称作生产 p99。没有用户 trace 时先用固定种子合成 trace，
公开分布与局限，不阻塞基础建设，也不将其称作真实业务负载。

**验收：** A/A 揭示噪声范围；不同执行顺序语义校验一致；回退被复现并归因，或明确标记
“尚不能稳定归因”；所有新结论可由指纹、原始样本与计时边界追溯。

### N4 — 池与回收的实际负载，P1/P2，依赖 N3

先测固定容量、混合容量、双峰容量和阶段切换；缓存规模 1/8/64/256，线程数
1/2/4/8。比较无池、共享池、线程局部池，保证**总空闲预算相同**，而非每线程各给一份
同额预算。负载覆盖冷启动、暖态、突发—空闲—再突发、并发 clear、池句柄先于 owner 销毁。

测命中率、扫描与锁持有/等待、吞吐、独立操作延迟、空闲 RSS 曲线和系统调用数。
先用现有 API 得到不同空闲时长的成本曲线，并分成两条生命周期不同的实验：

- 存活 owner 先 shrink/save，再 reclaim，随后再增长；reclaim 只处理逻辑末尾之后整页。
- owner 归池后保留或 clear，随后重新获取；池没有对已缓存映射调用 reclaim 的公开接口。

固定相同 live 数据与后续工作，分别计量缩小、回收、归还/释放和再次使用；不能把
reclaim 的 NoOp 或不同生命周期当作同一个回收对照。

- 容量扫描确为瓶颈时，实验按容量索引；先准备索引存储，保留归还无分配契约。
- 锁内解除映射确为瓶颈时，实验无分配的摘取空闲项后锁外释放；明确 clear 的线性化点，
  并发新归还项允许留到下一次 clear，不损坏预算或 owner 生命周期。
- 仅在共享池争用有证据时研究分片；保持全局预算，不把预算按分片数放大。
- TTL、后台回收、容量分档匹配均需独立收益证据和语义评审，首版不增加。

**验收：** 原固定容量收益不被无解释地牺牲；混合/并发边界不超预算，清零和生命周期通过；
锁或索引优化必须在非插桩构建上重测。无稳定收益则保留 F 池实现并交付适用范围报告。

### N5 — Automatic 的布局与失败成本，P2，依赖 N3

将初始容量、最大容量、插入节奏（256/1024）、突发长度和其他对象寿命独立参数化。
同一 trace 分别执行预分配、Explicit 重试与 Automatic；同时记录新块、缓存转移、
尾部扩展、容量边界、搬迁字节及 used_end，解释已有 +6.60% 的具体分配链。

候选只改变已证明有问题的内部增长/复用顺序，先不增加公开增长系数、多个策略枚举。
区分“减少调用者重试”和“减少机器工作”；不能靠吞掉失败、超出硬上限或变相预分配取胜。
覆盖嵌套构造中后续失败、OS 失败、缓存先于增长、最大容量边界和策略随 move/swap 转移。

**验收：** 相同 trace 能解释空间差异；优化若采用，应减少目标浪费且不增加不可接受的
复制/延迟。不能同时改善时，保留显式策略与已知权衡，更新建议，不扩大默认行为。

### N6 — 分配器候选筛选，P2，依赖 N3，可与 N4/N5 并行研究

先固定查找/合并策略，只实验切分；另一路固定整块复用和选块规则，隔离索引成本。
Core 与 wire 分别开关、分别测量，避免重复 E 的耦合错误。

| 实验 | 设计 | 需要回答的问题 |
|---|---|---|
| A：保护尾块 | 首适配切分，但物理尾部 donor 整块复用 | 能否保留空间收益并消除尾块身份丢失？ |
| B：替代切分 | 尾部 donor 从高地址端分配，保留空闲前缀 | 能否同时保留新存活块的尾部身份与可用残余？ |
| C：索引实验 | Core 稳定槽位＋尺寸分桶＋非空桶位图；相同选块规则的线性查找作对照 | 扫描/erase 成本是否值得支付索引成本？ |
| D：延迟合并 | 无合并与分配失败/缓存转移后的批量合并比较 | 空间收益能否抵消延迟与元数据维护？ |

A、B 为替代候选，先分别测。B 必须检查实际地址对齐、header、最小残余和物理末尾；
无法合法切分则整块复用。C 必须先定义 donor 选择与同尺寸 tie-break：分桶本身可能
改变 F 的首适配选择顺序，从而改变布局和尾块身份。用相同选块规则的线性查找隔离
索引成本，再用 F 作端到端采用对照；改变选块规则的变体标为“索引＋选择策略”，
不能把全部差异归于索引。C 不宣称无条件 O(1)：同桶大小/对齐仍可能扫描；有界快查
之后必须有完整后备查找，不能仅因扫描预算耗尽就遗漏可用块。精确树可作成本对照，
不直接上双树。D 在前三项证明有效且剩余碎片确有收益空间后再启动。

元数据先检查和准备，再无抛出发布。切分资源不足回退整块；wire→Core 若新设计要求
额外元数据，应先准备再摘链。第二索引失败不能留下半发布状态。首轮不提升整个库的
释放 OOM 保证；如要求 free 永不分配，必须另设 metadata credit 设计，处理加载重建
和原始 Core 没有完整分配图的回退，列出额外宿主内存预算。

**正确性与压力：** 区间参考模型驱动随机 allocate/free/expand/flush/save-load；
正序、逆序、随机、冷热释放；小/大/双峰尺寸、超页对齐、两波不同尺寸压力。逐步核对
存活数据、不重叠、唯一所有权、索引可达和计数。专测尾块复用后再增长、残余被占用、
跨层相邻、对齐空隙与仅差一个 header 的残余。fail-after-N 覆盖新增槽位、第二索引、
加载重建和缓存转移；同时报告安全性与损失的可复用字节。

**采用：** 只有独立候选先通过才组合；最终源码重新跑兼容矩阵。未通过则保留 F，保存
可复现实验及拒绝理由。禁止用每次释放全表合并、全局精确最佳适配或修改 V1 换取漂亮单点。

### N7 — 输入输出与只读视图，P3，依赖 N3 的端到端证据

首先选择一个实际文件/网络输入输出消费者，测完整读取、验证、保存与发送过程。
需要区分三个不同项目：

| 方向 | 可能收益 | 必须先解决 |
|---|---|---|
| 复用现有 owner 的 load_into | 减少映射、注册和释放；仍可能复制整个输入 | 失败后旧对象是否保留、引用/epoch 失效、部分写入不能发布 |
| 直接读入新 staging arena | 若上游确有中间缓冲，可减少一次复制 | 长度上限、短读/取消、校验后一次发布、失败 RAII 清理 |
| 分段 save / 外部只读视图 | 可能减少输出副本或输入拥有副本 | header 所有权、规范化、验证边界、异步完成前冻结与寿命、只读限制 |

现有 `bytes()` 是当前 owner 的借出视图，不是外部输入的无复制装载。也不能只返回
两个 span 就声称异步发送安全。复用 owner 的 load_into 对照必须包含 F 的池化加载，
避免重复计算现有池已取得的映射收益。各候选按自身拟消除的成本占比和端到端收益
决定是否继续；若收益不足，或调用端不能提供所需寿命保证，则记录不采用，不新增公开 API。

## 7. 统一验收与停止条件

以下性能阈值是**拟议采用标准**，不是已有实验结论。先用 A/A 标定噪声再锁定，
不能在看见候选结果后为它放宽标准，也不追溯性地撤销 F 已记录的采用决策。

- 正确性、生命周期、失败原子性、硬上限、wire 兼容和平台状态是硬门槛。
- 时间优化目标：目标负载至少约 5% 可重复耗时收益；复杂索引目标至少约 10% 时间收益
  或 15% 有用空间收益，且明确宿主元数据和维护代价。空间/驻留优化提前登记所需的
  空间收益和允许的耗时、再增长代价，按对应指标验收；例如消除 Automatic 的空间
  增量且耗时持平，仍可构成有效改进。功能修复不受提速门槛限制。
- 默认历史锚点以不超过约 2% 的新增耗时回退为预算；若环境噪声无法分辨该量级，
  增加独立窗口或报告不确定，不用“p 值不显著”证明等价。默认不接受可重复超过 5%
  的回退；介于二者之间须记录明确的目标收益与成本权衡。
- 共同工作耗时、固定容量成功数、used_end、wire 长度和宿主元数据分别报告。
  空间收益不能仅以高水位下降代表，也不能以完成更少工作换取更短时间。
- 7 对样本用于筛选；边界差异追加至少三个独立窗口、配对分布和区间估计，IQR 不当作
  置信区间。尾延迟需要足够独立事件样本和明确采样方法，不以 7 个批次推算 p99。
- 最终每个被采用候选使用同一冻结源码完成适用的全量、sanitizer、TSan、旧新 wire
  两轮修改和跨平台验证；记录新增测试后的实际数量，不机械沿用 46/26/15/420。
- 不通过的候选回退到 F 或已通过的独立部分，并归档反证。若跨平台收益不同，保留
  显式策略和平台范围，不强行设置全平台默认值。

交付物应包括：最终源码清单、工具链清单、功能与平台矩阵、性能原始数据和摘要、
负面结果、迁移/消费示例，以及每个工作包的采用/拒绝/前提未满足状态。
