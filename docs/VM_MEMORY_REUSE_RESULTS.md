`07d649909d7f43ca0d11b85accb6d9dab991e284`；没有切换分支、提交或推送。

完成候选实现、针对性实验和采用判断，不把候选通过正确性测试等同于适合默认启用。

采用四项：可选 Automatic、显式有界池、显式尾页回收、窄条件 POSIX fresh-load
直接 RW 映射。两层最佳适配/切分和 Core 合并完成了实现及验证，但性能门槛未通过，

## 加载回退诊断

旧实验的 64 KiB 重复加载有约 11–14.5% 聚合回退，本轮没有把它直接归因于 owner
索引。将 V1/B/C/D 放进同一个可执行文件、同一进程，固定输入和完整验证，分别测紧密
循环与带 Mach 查询/完整 wire hash 的间隔模式。两次独立运行未复现稳定 V1→D
回退：紧密模式约 6.013→5.769 µs，带间隔约 5.282→5.282 µs。
这不是旧 runner 的逐指令重现，也不能据此声称旧回退已修复。

仅诊断快照的分段计时显示 D 的复制/首次触页约 4.45–4.94 µs，占约 82%；
预留约 0.24 µs、权限启用约 0.34 µs、注册约 0.08–0.10 µs，图校验约
0.12–0.13 µs。带插桩的分段值不用于最终端到端提速声明。

窄条件候选仅作用于 POSIX、非池化、非空且输入长度等于硬上限的 fresh load。
它把预留和初始权限启用合并；所有输入仍完整复制，所有校验仍保留。两次独立
7 对实验中，紧密模式 5.794→5.479 µs，带间隔 5.823→5.507 µs，配对比约
1.064/1.067。默认 64 MiB 预留的小输入不符合条件，不能外推这项收益。

## 策略契约

`XGrowPolicy::Automatic` 是显式选择，现有 API 默认仍为 Explicit。几何增长受固定
`maximum_capacity()` 限制，分配与尾块扩展在成功启用和准备页面后才发布元数据。
新块分配先尝试当前逻辑范围并释放 wire 缓存，再允许增长；存活尾块优先原地扩展。
OS 失败直接抛 `XBadAlloc`，不会在备用分配中静默重试。后续元素构造失败可能保留
已经增加的容量。策略随 move/swap 转移，不进入 wire；compaction 创建独立默认 owner。

`reclaim_tail_pages()` 只处理逻辑末尾之后的完整页，保留基址、epoch、逻辑长度、
末页有效字节和预留空间。默认 save/shrink 不回收。返回值区分完整成功、无工作、失败，
以及 Linux 丢弃成功而撤销权限失败；字节计数描述完成的系统操作，不等于实测 RSS。
重新增长依然清零。Windows 使用 MEM_DECOMMIT；Linux 使用 MADV_DONTNEED 后
撤销权限；macOS 原子替换自己拥有的废弃尾页，未采用先解除映射再抢回地址的方案。
参见 [Windows VirtualFree](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualfree)、
[Linux madvise](https://man7.org/linux/man-pages/man2/madvise.2.html)、
[XNU 映射替换](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_mman.c#L670-L684)。

`XBufferPool` 是共享的显式有界池，同时限制空闲映射数量、预留字节和可访问字节，
精确匹配硬容量。预算不包括存活 owner。池状态由存活 owner 持有，空闲 owner 不反向
持有池，避免环；释放前先退出 owner 注册表。归还/move/swap 不分配宿主内存。
普通复用清零完整逻辑区，加载完整覆盖输入，旧脏尾部再次暴露前清零。`clear()`
仅释放空闲映射，存活 owner 仍有效且以后可以再次归还。默认空池句柄不分配内存。

## 完整分配器候选的反证

E 保持 wire ABI，最佳适配、切分及 Core 物理相邻合并均通过针对性测试和双向旧版
加载/修改/保存。Core 和 wire 缓存分别拥有空闲块，必须先转移所有权再合并；不能
吞掉未知对齐空隙。候选的正确性通过并未消除其负载相关成本：

| D → E，共同工作量 | 耗时中位数 | 共同阶段 used_end | 后续 1 KiB 压力成功次数 |
|---|---:|---:|---:|
| Core 大块→小块 | 0.392→3.245 ms | 6,701,232→4,292,784 B | 2,630→5,561 |
| wire 缓存大块→小块 | 1.819→4.414 ms | 6,832,400→4,423,952 B | 2,504→5,435 |
| Core 相邻合并 | 0.739→1.225 ms | 3,801,264→2,212,016 B | 7,467→6,947 |

Core 切分例的主要新增成本在复用阶段（0.308→2.967 ms），释放也从
0.011→0.200 ms。最佳适配遍历候选，合并扫描 Core 空闲表。合并减少当下 high-water，
却可能留下不足下一轮请求大小的残余，不能承诺所有压力分配都增加。
增量交错增长还出现 4,235,792→6,308,240 B 的 used_end 增长（约 49%；wire 长度分别再加 88 B）；
预分配交错锚点反而节省空间。复用顺序与尾块身份会改变后续增长路径，单一模拟
无法替代这些实测。
两种交错实验除初始容量外，插入节奏也不同（每 256 与每 1024 次），不是只改变
增长策略的单变量实验。

进一步用相同 E 快照分别关闭合并、将最佳适配改为首个合适块、同时关闭二者。
隔离实验再次复现原回退。首适配显著减少扫描成本，但“首适配＋不合并”的 Core
共同负载仍为约 0.719 ms，对照 D 约 0.400 ms；交错增长仍使用 5,255,568 B，
比 D 多约 24.1%。仅关闭合并不能消除最佳适配的扫描成本，仅改首适配也不能消除
切分残余占据物理尾部造成的增长路径变化。正式 F 恢复 D 分配器，而非将未解决的
回退藏在新的默认策略中。

后续若重新研究分配器，应同时解决按大小查找的索引成本、切分残余与存活尾块扩展
的协调、随机释放顺序的元数据成本及无宿主内存时的失败原子性。此次没有把更复杂的
双索引或跨层邻接扩展临时加入正式代码。

## 最终 F 的效果与代价

最终 F 重新测量了全部 20 项对照，包含 13 项针对性比较、5 个历史锚点和 2 个旧
增长/追加检查，共 280 个正式样本、40 个预热样本。它们使用 F 冻结源码；E、隔离
归因和加载诊断是另外的数据集。以下“配对倍数”均为每对 before/after 耗时比的中位数，
不是两个总体中位数的商；IQR 是样本四分位范围，不是置信区间。

| F 同一二进制，关闭→开启 | 测量中位数 | 配对倍数 / IQR | 采用判断 |
|---|---:|---:|---|
| 池：256 个 64 KiB buffer × 8 批，创建＋销毁 | 9.782→2.062 ms | 4.809 / 4.663–4.852 | 显式启用；暖批次 1.217→0.134 ms |
| 池：128 个 64 KiB 消息 × 8 批，verified load＋销毁 | 6.739→1.525 ms | 4.348 / 4.325–4.456 | 显式启用；暖批次 0.830→0.110 ms |
| Automatic：100 万元素顺序追加 | 4.099→3.955 ms | 1.042 / 1.007–1.059 | 主要收益是重试 11→0，不承诺显著提速 |
| Automatic：100 万元素交错追加 | 4.093→3.972 ms | 1.040 / 1.003–1.051 | 重试 11→0；used_end 增加 6.60% |
| 尾页回收：64 MiB，4 轮缩小/回收/再增长 | regrow 合计 2.015→12.676 ms | 总过程 0.138 / 0.137–0.139 | 保持显式；另付约 1.954 ms 回收时间 |

池以保留内存换取重复创建速度。创建负载空闲时缓存 16 MiB 可访问页，进程 RSS
约 18.188 MiB，清池后约 2.188 MiB；加载负载空闲时缓存 16 MiB 预留、10 MiB
可访问页，RSS 约 12.250→清池后 2.250 MiB。没有把这些缓存内存说成被释放，
也没有以这组串行实验外推多线程争用性能。

回收负载的可访问页从 64 MiB 降至 16 KiB，进程 RSS 约 66→2.016 MiB，但再增长
要付缺页/初始化成本。返回的回收计数与这些独立的 RSS 观测分别保存。Automatic
交错负载 used_end 为 4,235,792→4,515,392 B；两者逻辑长度均为 8 MiB。
启用 Automatic 会改变复用/增长顺序，因此不保证空间布局或 wire 长度相同。

恢复 D 分配器后，三项默认碎片负载 D/F 配对比分别为 0.969、0.972、1.015，
压力成功次数和 high-water 布局与 D 一致，消除了 E 的倍数级回退和布局恶化。
其他默认策略锚点也保留了负面结果：

| D → F 默认策略 | 总体中位数 | 配对 D/F / IQR |
|---|---:|---:|
| exact-capacity 64 KiB × 64 verified load | 0.3452→0.3248 ms | 1.0679 / 1.0588–1.0750 |
| 64 MiB 首次 verified save | 3.9547→4.1061 ms | 0.9688 / 0.9296–0.9814 |
| 100 万元素预分配 arena 尾部追加 | 2.8128→2.8797 ms | 0.9768 / 0.9669–0.9983 |
| 128 MiB grow 检查 | 见原始汇总 | 0.9940，IQR 跨 1 |
| 1000 万元素预分配 arena 追加 | 见原始汇总 | 1.0066，IQR 跨 1 |

加载的稳定方向支持采用窄条件直接 RW 优化，未改变默认大预留下的小输入路径。
本轮 save 与尾部追加分别观察到约 3.2% 和 2.4% 的配对耗时回退；不能宣称“全面
提速”或“零回退”，也没有证据把这种差异唯一归因于某一个源码分支。其余锚点的
完整分布保留在证据中。当前接受四项功能及以上小幅成本，同时拒绝 E 分配器的
大幅回退；默认增长、池和回收策略保持兼容。

策略测试覆盖小初始长度的 bootstrap、硬上限、超页对齐、Reserve/Enable/Prepare
失败、尾块失败不静默重试、缓存先于新块增长、move/swap/Core 转移、坏帧拒绝、注册
失败归还池、脏区重用和回收后再增长。另加入嵌套记录复制：第一成员先成功触发增长，
后续成员达到硬上限而失败，原有记录不变，仍能保存加载，再用更大容量成功重试。
允许失败后保留新增容量，与实际异常契约一致。

独立审查覆盖了分配器原型、池引用寿命与锁顺序、Automatic 元数据提交、direct-RW
失败清理及最终 D→F 差异，未发现尚未处理的确定缺陷。E 的 47 项本机测试记录仅
证明候选正确性；正式结论使用 F 的 46 项及上述固定源码哈希。

性能证据审计重新计算全部中位数、IQR 和配对比，并核对压缩原始数据、源码归档及
共同语义 checksum；本轮所有数据集合计 1008 个正式样本、144 个预热样本。最终
验证包还核对了 479 个证据文件哈希和 76 个源码哈希。归档保留编译器/依赖版本、
完整命令、失败边界和平台限制；复现说明见两份证据目录的 README。
