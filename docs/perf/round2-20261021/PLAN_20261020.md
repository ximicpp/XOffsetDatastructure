## 结论摘要

在不改 V1 格式、输出仍是新 `std::string` 的前提下，这一轮最可能做到 8/12，最好 10/12，最差维持 7/12（全部是推断）。推荐路线是：先在 Mac 上做 5 个只诊断、不计成绩的短测量，用它们决定哪些候选值得实现；再按"输出 → 校验 → 修改"的顺序各筛选一次；最后合并做一次正式验收。

- **最有把握的一步是 E1**（输出前用一次 `madvise(MADV_WILLNEED)` 批量缺页）。改动约 20–30 行，输出字节不变，估计输出快 3–15%。到 4% 能让 FlatBuffers 稳过，到 9% 能让 cista 也过。先跑约 5 分钟的独立探针 P1，省不到 5% 就关闭。
- **修改对 cereal 从"不可达"改判为"边缘"**：分配器层约占修改的 47%（剖析，非 W9a 二进制）。全部候选做上，中心估计上界约 1.08，乐观约 0.99。这会重开上一轮 D3 (a) 已结案的一项，并需要重开 M1（和 D4 (a) 冲突），所以要你决定（Q4、Q5）。
- **读取对 cereal 只剩 1% 余量，差距全部出在修改之后**（query\_before 0.927，query\_after 1.147，实测）。D1 允许辅助项上界到 1.02，足以把这一项翻掉，所以建议读取单独收紧到 1.01（Q12）。
- **两项判为不可达**：独立输出对 Cap'n Proto、对 cereal。依据见"现状与目标"。
- **我不采纳业界调研的一条推荐**：I1（短字符串内联）和 I2（去块头）会让旧读取方读不了新数据，超出 D2 的授权，也违反 V1 兼容这条基本约束；它们和 E1 争的是同两项输出，E1 便宜得多。建议这一轮不做原型，只在云端算字节账，E1 失败后再交你决定（Q13）。
- **需要你审定的共 15 项（Q1–Q15）**，见"决定清单"，其中 Q4、Q5、Q13 和你已有的决定直接冲突。按你 16:01 的指示，计划里每一项都已按推荐写入。

这一轮只合成计划：没有改仓库，没有在 Mac 上计时。四份调研报告原样保留，这份计划只引用它们。

### 为什么两项判为不可达

- **输出 ÷ Cap'n Proto**：Cap'n Proto 的输出本身就是一次整块复制（适配器是 `messageToFlatArray`，核对过源码）。即使目标页已驻留，复制 17.22 MB 也要 0.32 ms（实测 B3），刚好在线上；输出必须是新内存，缺页和清零省不掉。所有候选叠加，包括会改格式的 I1+I2a+E1，也只到约 0.41（推断）。
- **输出 ÷ cereal**：要省约 0.30 ms，相当于缺页成本的约 45%。E1 最多省 15%，到约 0.236；I1+I2a+E1 约 0.201，仍在线外，而且要改格式（推断）。V1 格式下减字节的路已全部关闭：B5 重放证明换分配策略省不下字节（实测），输出时压缩（E2）预计净亏 0.3–1 ms（推断）。
- 两项都按 D3 (a) 处理：目标不动，不再开机制，带证据报告未达。如果不复制的输出计入成绩，输出四项都会过，但你已按推荐定为不计（Q2）。

## 冲突与叠加

各方向的候选大多改的是不同代码，可以叠加；真正需要裁定的是下面 7 处。每处写了我的裁定，和你已有决定相关的在决定清单里再列一次。

1. **I2 和"块头不能删"。** 输出报告说块头是 V1 格式的一部分，不能动；业界报告建议去掉或缩小。两份报告在事实上其实一致：I2 一定让旧读取方读不了新数据。分歧只在这一轮要不要往这个方向投入。**裁定**：按 V1 兼容这条你定的基本约束，输出报告的结论成立，I2 归入将来的 V2 格式方向。是否放宽由你在 Q13 决定。
2. **I1 会同时动读取、修改和校验。** 读取端 `data()` 多一个分支，而 cereal 读取只剩 1%；修改端会少约 2 万次分配和释放，和 α/β 两组改的是同一批容器代码（`XFixedString::assign` 等）；校验要加内联形态的检查。**裁定**：即使将来要做，也必须排在 α/β 和 V-A 定稿之后，否则两组的筛选基线会失效。
3. **I1 和 E1 争同两项输出。** I1 让 wire 少约 9.7%，预计也是拿下 cista 和 FlatBuffers 两项输出；E1 不改格式、改动 20–30 行。**裁定**：先 E1。E1 拿下两项，I1 对成绩就没有增量；E1 没拿下 cista，I1 是剩下唯一的路，那时再问你要不要改格式。
4. **V-E 会改变"加载后再输出"的字节。** demo 里输出在重载之前，计时的输出不受影响；输出仍是 V1，旧读取方能读，所以不超出 D2。但"加载后输出等于输入"和 B7 类的等价旁证会失效。另有两点报告里没写：
   - 第一次加载的输入没有空闲块、本来就是顺序布局，搬迁只会把一次 memcpy 换成 20 万次小复制加改偏移，加载可能变慢，撞上 D1 的加载否决。**裁定**：只在空闲字节占比超过阈值时搬迁（阈值在 D-R1 后定），输入无空闲时走现在的 memcpy。
   - 搬迁后没有空闲链表，重载后再修改的 O(n²) 扫描也就不会发生。V-E 如果进来，Q14 的单独修复可以缓做。
5. **D1 的 1.02 和读取的 1% 余量。** D1 允许候选让读取上界到 1.02，但读取对 cereal 是正式目标，1.040 乘以 1.02 是约 1.061，会把这一项翻掉。每个候选单独过 D1，叠加后也可能超。**裁定**：读取的辅助项收紧到上界 ≤1.01，其余辅助项仍按 D1（Q12）；最后的组合筛选里读取用同一条。
6. **修改候选和输出余量。** wire 每多 172 KB，输出就慢约 1%。α/β 两组都承诺不改分配决策、wire 逐字节不变，所以不影响输出。**裁定**：把"和 W9a 逐字节相同"作为两组进筛选的硬门槛，不一致就退回诊断。重载后再修改的修复和 R-C 会改分配决策，所以都不进本轮。
7. **B1 改 VM 预留区布局。** 宿主页不在 wire 里，不影响输出和 V1；但加载多一次写（T 当年就是因加载被否决），且和交出所有权接口有交叉：将来做那个接口时，交出的存储要清掉宿主页里的 OwnerRecord。**裁定**：允许（Q8），加载按 D1 看。

可以直接叠加、不需要裁定的：E1 只动输出复制那一处；V-A/V-B/V-C/V-D 只动校验；α/β 只动分配器和容器。三块代码不重叠，各自对 W9a 筛选后再做一次组合筛选即可。业界报告里的 I3、I5 分别就是 V-A、E1，已合并。

## 实验基线

所有实验以 W9a 的库源码为基线，也就是 next\_cpp26 9e3602f 上的 `xoffsetdatastructure.hpp` 和 `xoffset_virtual_memory.hpp`。主线上没合并的三个 PR 都不改这两个文件，合与不合都不影响计时可比性：

| PR | 改什么 | 对实验的影响 |
| --- | --- | --- |
| #3 移出证据 | 清单和交接文档；删除 `handoff/`、`docs/coordination/` 等约 254 MB | 对比工具和冻结的正式工具在这两个目录里。合并后从 tag `archive/claude-mac-candidates-20261020` 取，或用 Mac 上已有的副本，并核对哈希 |
| #4 修 CI | 结构检查、stage3 测试、validate\_vm 的输入 | 只动测试和 CI，无影响 |
| macOS/Windows 构建修复 | `VERSION` 改名 `XOFFSET_VERSION`；测试里两个变量改名 | 库代码不变；引用 `VERSION` 的脚本要跟着改 |

做法：

1. 实验分支从开始实施时 next\_cpp26 的最新提交拉出。三个 PR 如果都已合并，就是合并后的头；没合并，就从 9e3602f 拉，以后再合入。
2. 每次筛选前核对基线的这两个头文件和 9e3602f 逐字节相同；不同就停下来查，不接着计时。
3. 对比工具用 W9-formal-mac-v1 那份（迁移包里的 alpha 时期适配器），冻结文件哈希，和上一轮一致；每次筛选和正式验收都用同一份。
4. 筛选的对照组一律是 W9a；只有最后的组合筛选是"组合 对 W9a"，然后新冻结一次正式验收。

## Mac 实测顺序

Mac 上同一时间只有一个会话，计时期间不编译、不跑测试；只计数的诊断可以和构建交替。顺序分三段：先诊断，再按"能增加通过项的先做"逐个筛选，最后组合验收。每一步的启停判据写在表里；标"我定"的门槛是本计划新加的，其余来自各方向报告。

### 第 0 段：云端，不占 Mac

- 按 SPEC 和已有的空闲块统计，算清 I1/I2 各能少多少 wire 字节（只计数），供 Q13 将来使用。
- 写好 P1 探针程序和各诊断开关的补丁草稿，交给 Mac 编译，缩短 Mac 占用。

## 风险、停止条件与资料

### 风险

- **估算偏差**：所有收益都是推断。修改的分配器占比来自 G1+D1 的剖析，不是 W9a 二进制；E1 的异常进出占比没测过，业界旁证（16 KiB 页、Linux 约省 30%）偏向区间低端。
- **读取余量**：cereal 读取 1.040，任何候选让读取慢 1% 以上都会丢掉一个已过项。Q12 的护栏和组合筛选是两道防线。
- **批次波动**：输出比值在批次之间波动约 2%（W7 0.196 对 W9 0.2004），E1 低于 4% 时 FlatBuffers 一项仍可能落在线外。
- **平台**：E1 只在 Darwin 启用，效果依赖 macOS 26.3 的 XNU 是否已有对应代码，P1 会确认。B1 改预留区布局，要三平台 storage 套件都过。
- **V1 兼容**：没有旧机资料。排进本轮的候选除 V-E 外都不改 wire 字节，兼容性靠与 W9a 逐字节比对传递。
- **单机计时**：筛选和正式验收期间 Mac 上不能有其他会话编译或计时，包括主线 PR 的工作。

### 停止条件

1. 第 1 段任一判据不满足，对应候选关闭，不换做法重测。
2. 功能门禁或字节比对失败：先诊断，修正后重走门禁，不靠计时结果放行。
3. 每个候选或组只筛一次；未晋升就关闭，不补样、不换种子。
4. 组合筛选未晋升：停下，把各单项和组合的结果拿回给你，不自行重组。
5. 任何需要你决定、却不在本清单里的分叉，停下来问你。
