## 3. 各步判据

| 步骤 | 判据 | 结果 |
| --- | --- | --- |
| 1 设计 | 校验能力不能变弱（否则停下问 susu） | 没有变弱（设计第 6 节逐项对照），自动推进 |
| 2 I1 原型 | query_before ≤ 1.01×W9a | 0.968 [0.940, 0.998] |
| 3 无块头 + 新分配器 + N6/N7 | 修改 ≤ 0.85×；wire 累计少 ≥15%；reload 后修改无 O(n²) | 修改 0.675；初始 wire −28%，变更后输出 −22%（稀疏后 −27%）；重载快照再跑某阶段 ÷ 连续跑，W9a 在 3/4/6 阶段为 5.5/11.4/25.8 倍，V2 为 1.3/1.4/1.8 倍 |
| 4 新校验器 | 差分和 fuzz 零不一致 | 普通构建 10 万例、ASan+UBSan 3.5 万例，0 不一致，无内存错误 |
| 5 稀疏 wire 计数（N10） | ≥4 KiB 空闲区占 wire ≥3% 才实现 | 5.86%（S/M/L 相同），已实现 |
| 6 E1 + 筛选 | 72 对规则 C 晋升 | 晋升 |
| 7 正式验收 | ≥7/12、读取 4/4、新门禁全过 | 10/12、4/4、全过 |

- 第 4 步的 fuzz 比对四方：按格式规则独立写的参考检查器、类型化校验、raw 校验、已验证接收路径。被接受的输入还要再修改、保存、重载，并且字节稳定。
- 第 5 步的大空闲区来自第 4 阶段新分配、第 7 阶段又删掉的那 2048 条记录的 payload，正好连成一片。
- 稀疏 wire 第一版让输出慢了 13%，原因是找连续空洞的扫描太慢（101 µs）。改成先找全 1 位图字后降到 29 µs。之后稀疏 ÷ 不稀疏：输出 0.960 [0.916, 1.006]，reload 0.965，wire 再少 5.9%。
- E1 让输出约快 7%（0.933 [0.905, 0.962]）。

## 6. susu 的决定在实现中的落点

- **N3**：读取时先查 magic 和主版本，V1 输入明确报错。
- **N6**：所有权检查由 `XOFFSET_MOVE_OWNERSHIP_CHECKS` 控制，默认只在未定义 `NDEBUG` 时开启。测试是 Debug 构建，仍覆盖这些检查；demo 是 Release 构建，不查。
- **N7**：新增 `XFixedVector::assign(first, last)`。XOffset demo 适配器第 4 阶段改成一行 `r.payload.assign(op.bytes.begin(), op.bytes.end())`，与 cereal 的一次 vector 赋值写法对等；另外只改了库标签 `xoffset-mac-r3-v2`。适配器差异见 `round3-adapter.diff`。
- **N8**：E1 不算预触页，重新启用，取代 01:12 的 Q1(b) 裁定。形态沿用 P1：Darwin、输出 ≥1 MiB、每 256 KiB 一段 `madvise(MADV_WILLNEED)`。
- **N9**：完全去掉块头，活块大小由容器头推出。设计阶段确认校验不依赖块头。
- **N10**：已计数并实现（见第 3 节）。
- **N13**：设计没有发现校验能力变弱，全程自动推进到正式验收。

## 7. 公开 API 变化（N2）

完整清单在 `docs/V2_FORMAT.md` 第 6 节。要点：

- **删除**：`XAllocatorStateV1` 及全部相关接口、`AllocationHeader`、V1 wire 头和 V1 常量（只保留 `XWIRE_MAGIC_V1` 用于拒绝）、FreelistIndex 诊断。
- **变化**：
  - 绑定只剩 `{XArena* segment}` 一种。
  - `deallocate`/`try_expand` 需要传块大小。
  - 接收和 raw 校验要带空洞表与稀疏区段表。
  - `VerifiedSnapshot::segments()` 改为 3 段。
  - 不可达的 arena 内存必须在 verified 保存前释放。
- **新增**：宿主侧空闲表接口、`WireHole`、`XWireHeaderV2`、`assign(first, last)`、内联串查询接口。

## 8. 改测试时修掉的库缺陷

1. **超对齐分配**：原来对齐的是 payload 偏移，不是地址。payload 基址只按页对齐，所以 32 KiB 以上的对齐会错位。
2. **超对齐尾块不能原地扩容**：现在任何对齐的尾块都能原地扩容。
3. **new_handler 回调期间 owner 被移动、交换或释放时会破坏空闲表**：现在先在旁边准备好宿主分配，再经注册记录重新解析 owner，然后才发布；被替换的宿主存储在发布之后才销毁。
4. **已验证接收时 owner 在校验前就可见**：现在只在 `publish_received` 时发布。

另外两处是我在 V2 改动里自己引入、随即修掉的：raw 校验函数被误删，`XArenaAllocator::deallocate` 漏传块大小。
