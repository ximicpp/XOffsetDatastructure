## Actual opportunity and minimal patch

The retained original-driver assembly already establishes up to four data resolutions on the nonempty XFixedVector<Attr> containment-miss path: original lines50761/50785/50795/50804, also present in R1 at52237/52272/52291/52304. This proposal requests only a candidate bare compile to verify 4-to-1, never a new control compile to rediscover that fact.

In the non-string owning branch, capture `const auto* elements = value.data()` once, apply the original capacity-times-element-size containment predicate and immediately return on hit. Only after a miss and only for nontrivially-copyable element types, read `value.size()`, compute `elements ? elements + count : nullptr`, and iterate to that end. The exact original recursive expression `move_assignment_owns_address(child,address)` remains. Array, string, trivial element and reflected-base/member semantics remain. No owns boolean is cached; assignment's two directional ancestor checks are unchanged. Capacity remains ownership extent, size remains live recursive iteration extent.

## Differential lifetime and callback proof

data() calls resolve_rel32_const, which reads the relative integer, invokes canonical_bytes_at for a nonzero target, launders a pointer from a real canonical origin if available, otherwise follows the existing legacy character-pointer arithmetic. Resolution does not allocate or dispatch wire policies. The closed C14 canonical helper preserves its acquire check, live record/bounds checks, registry mutex and nonallocating cold lookup. Its cold result is never installed into TLS; a local live record is retained by its owner/registry and cannot be the internal last record release. This explicitly closes the earlier replaceable-delete eviction risk; noexcept alone would not have proved it.

Between the new capture and the old range-for's begin/end setup, successful paths execute only builtin capacity math, the unchanged containment predicate, type selection and size reads, plus the old repeated resolution calls just proved callback-free. The data pointer and end would therefore be the same. The new loop does not extend a pointer over a boundary that the original range-for had not already crossed: the old loop also retained its begin/end throughout recursive calls.

Do not generalize this into 'all generic owns recursion never calls user code.' The unqualified recursive expression can be found by ADL for an application type; reflected traversal invokes the existing internal lambdas, and the patch preserves that expression/order. Any supported recursive behavior faces the same captured-loop-pointer lifetime as before. No new cache crosses an allocation, mutation, comparison, wire hook or callback. In particular the unrelated L1 PMR context counterexample does not occur on the current-node repeated-resolution segment, and no L1 mapping pin is inferred.

Null data uses a null end and performs zero iterations, avoiding null-plus-zero arithmetic. A capacity hit does not read size or visit children. Trivial elements do not acquire an unnecessary size read. Empty live size with spare capacity still recognizes ownership of the entire head allocation and skips children. The API's preexisting valid-descriptor premise is unchanged; this is not a new malformed-descriptor admission or bounds bypass.
