# Mac 新实验协议草案（未冻结，未执行）

这是新宿主上的独立实验条件，不是旧 Q32/F64 或 72 对窗口的补样。冻结前可修改；冻结后（写入 SHA 与预算）不改阈值、不补样、不删点、不择快。

## 1. 宿主与身份
- Apple M4 mac mini（4P+6E，16 GB），macOS 26.3（25D125），原生 arm64，交流供电，lowpowermode=0，冻结时记录 `pmset -g`、`pmset -g therm`、`sysctl hw`、uptime、在跑进程清单。
- 工具链：p2996-d77eff1（`clang-21` a3a779ee…，`libc++.1.0.dylib` f4e4394b…），SDK MacOSX26.5，Release -O3，`-stdlib=libc++ -pthread`。
- 对比工具：恢复包 alpha 时期元数据（非 final-v4，后者 C++ 侧未转交），四竞品锁定提交，Mac 本机构建；二进制 SHA 冻结。
- 输入：本机由 `reference.py` 重新生成的 prepared-v1（S 档与 golden 逐字节一致）；M 档为主测，S/L 只做功能。

## 2. 被测对象
- 基线：R1+M2 候选（主头 155f0847…）与 C14（66818de4…）。
- 候选（每个单独筛选，收益不相加）：W3（固定地址窗口 + G1）、G1 单独、以及 T / O+R / N / G / E 中通过全量验证者（均在 W3 之上）。
- 组合仅在各自筛选有正证据后另行构建、另跑全门禁。

## 3. 调度与静默
- 唯一 heavy executor：计时期间不编译、不跑测试、不归档、不同时跑其他子 agent 的重任务。
- 不暂停用户的其他应用。记录但不控制后台活动（Spotlight、Time Machine 状态）。
- 无法硬绑核：用 `taskpolicy -c user-interactive`（或等价 QoS）启动子进程以偏向 P 核，并在每个子进程记录 `getrusage` 与（可得时）核类型；不声称独占物理核。
- `caffeinate -i` 保持唤醒；每个宏周期前后记录温度状态，出现 thermal warning 的周期按预注册规则作废并报告，不补跑。

## 4. 筛选（每个候选一次）
- 设计沿用旧 72 对：AB/BA 各 36 对，固定种子生成平衡次序，子进程独立，log 比，df=71。
- 主族：相对基线的 read_sum、mutate（单侧，上界 <1 为改善），t(1-0.05/4, 71)。辅助族：其余六阶段与 total，双侧 t(1-0.05/72, 71)。
- 晋升需要：主族上界 <1，且无辅助下界 >1（成本转移否决），且功能门禁已通过。
- 预算：child 上限与窗口时长由本机 A/A 试运行（不计入任何结论）测得的 max 推导后冻结。

## 5. 正式验收（筛选与组合之后）
- 口径不变：候选 ÷ 同批每个竞品，read_sum ≤1.05、mutate ≤1.05、原 demo 独立拥有 emit ≤0.20，联合单侧 95% 上界；reload 完整校验、只报告。
- 结构沿用 F64（宏周期、conditioning、warmup 剔除），周期数与预算按 Mac A/A 重新推导并冻结。
- 结论只限本宿主与本工具链；不与 WSL F64 数字直接比较。

## 6. 尚需用户决定
- W 系列的约定变化（指针来源、窗口上限与固定地址、普通区头部不能绑定接收区分配器、接收存储不进池、首次建存储即预留窗口、窗口失败时普通映射可能被挪开）。
- 写时复制是否算独立拥有输出（决定 Cap'n Proto emit 是否有路径）。
