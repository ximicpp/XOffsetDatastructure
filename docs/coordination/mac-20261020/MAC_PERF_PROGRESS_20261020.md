## 2. 机制与单独效果

| 机制 | 内容 | 单独效果（修改，相对其基底） | 语义变化 |
| --- | --- | --- | --- |
| W（W2） | 固定地址窗口 + 编译期常量范围判断 | 约 −35%~−40%（相对 R1+M2，含 G1） | 有，见 §4 |
| G1 | 扩容只清零曾暴露过的字节 | −4.7% | 无（接收存储保持全清零） |
| G | 扩容探测不抛异常 | −7.8% | 有：少一个 new_handler 回调点和一种 bad_alloc |
| O+R | 移动时空头早退、复用目标 binding | −5.8% | 无 |
| N | 分配记账内联快路径 | −4.1% | 无 |
| E | 空闲链表空类跳过 + clz 分类 | −2.5% | 无 |
| T | owner 查询 TLS 3 次→1 次 | −1.6% | 无 |
| MV | 叶子类型移动内联 owns/set_rel32/release | −4.2%（CI 不含 1） | 无 |
| P、NZ | reserve 前缀 memcpy、空头跳过 | +3%~+4%（变差，不采用） | 无 |
| RL、PF | Attr 重定位算术、owns 预取 | ±0（不采用） | 无 |

否定的诊断：D2（relaxed 读）、X1（普通全局 bool + 冷调用）、X2（运行时全局变量范围判断）对修改均无改善；`__builtin_expect` 标注窗口分支使读取变差。

## 3. 剩余差距

- **修改对 cista**（上界 1.089）：W5 上再做一次"完全不检查"诊断，修改还能快约 5%~8%。这部分是 W 为保留指针来源而付出的固定代价：每次解析多一次常量范围判断，外加对 launder 结果的选择，编译器无法证明两条路径数值相等，所以合并不掉。如果改用"降级指针来源承诺"，这部分就没有了，修改对 cista 预计会落到约 0.95。
- **修改对 cereal**（上界 1.59）：差距分散在各阶段；删除记录一步主要卡在适配器自带的 unordered_set 和公开的逐成员移动协议，现有约束下没有可证明的机制。
- **独立输出**：XOffset 约 1.06–1.18 ms，主要是新页缺页加复制；对 FlatBuffers 已在门槛边上（上界 0.201），对 cista 0.214、cereal 0.280。Cap'n Proto 输出约 2.0 ms，要求 XOffset ≤0.40 ms，用新页复制 17.8 MB 做不到，只有写时复制一条路。
- **重载**（只报告）：对 FlatBuffers 约 2.1 倍、cereal 约 1.75 倍、Cap'n Proto 约 1.6 倍、cista 约 0.95 倍。

## 4. 需要用户决定

1. W 系列的约定变化：指针来源改为进程窗口数组；窗口有上限并位于平台固定地址；普通区头部不能绑定接收区分配器；接收存储不进池；首次创建存储即预留窗口（256 GiB 虚拟地址，不占内存）；窗口失败时普通映射可能被挪开。**替代方案**：降级接收数据的指针来源承诺（不需要窗口，修改再快约 5%~8%）。
2. G 的行为变化。
3. 写时复制是否算独立拥有输出（决定 Cap'n Proto 输出是否有路径）。
4. "扩容后整体覆盖跳过逐元素构造"是否算重开 M1；库内默认复用退休内存区是否算改 demo。
5. 是否从旧机取回 final-v4 对比工具源码、V1 兼容与生命周期测试材料。
