## Mechanism and falsification

The unchanged adapter calls resize then std::copy for samples, payload and attribute value. In the control fresh suffix, each default_construct invocation evaluates binding even when scalar construction ultimately ignores the allocator. The hypothesis is that actual optimized code retains work there; the candidate removes that loop's binding evaluation. These are separate from the rejected allocation witness candidate, whose unit was a new allocation.

The first executable request compiles the original entire driver and adapter to assembly at bare -O3 -DNDEBUG, with no diagnostic macros or -UNDEBUG. Independent review must follow the actual uint8/uint32 fresh suffix call closure. If the control already batches equivalently, has no repeated binding work, or the candidate merely adds overhead, reject M1 before native tests/screening. The standalone m1_codegen.cpp wrappers are an optional local reading aid and are not substituted for original-driver evidence.

After codegen admission, the fixed-M diagnostic uses one control and one candidate process only. It retains original public calls, nine mutations, every stage canonical digest, both full query answers, original owning emit and validated reload. A derived diagnostic header counts entry/capacity/tail/fresh/element events and the actual fallback binding invocations, while a separately derived driver resets/dumps counts around each original stage. Candidate bulk elements must equal control fresh elements; unchanged path counts and all business checks must agree. This diagnostic is never a timing binary. Counts do not quantify CPU time or establish speed.
