1. 先确认真实可消除工作，再确认成本和收益；逻辑调用数不当作 CPU 周期占比。Amdahl 估计使用 `1-f+f/s+h`，不能承诺当前候选填平历史约35.6%的修改差距。

4. 一项失败只关闭该候选/窗口，继续其他独立工程；不滚动补样、不重开旧窗、不回收取消项的统计预算。

## 首轮候选集合

| ID | 独立变化 | 主目标 | 机制准入 | 否决条件 |
|---|---|---|---|---|
| M1 | 默认 scalar fresh resize 移除逐元素 binding 求值，适用时用标准批量值初始化 | mutate | 原 M 确实命中；真实优化配置下存在被消除的重复工作 | 已被编译器消除、命中不足、改变值初始化/事务/custom frontier |
| L1 | 未发布 copy-load owner 的验证上下文地址来源 | reload | 原全局地址恢复被上下文局部恢复替代，全部检查和错误顺序保留 | 生命周期/回调证明不成立、未知来源无原路回退、只增加间接开销 |
| R1 | canonical 零活跃 owner 热路与大段冷实现分离 | read_sum | 真实机器码仍有可消除调用/代码膨胀 | 原热路已最简、改变 acquire 或 TLS/回调行为 |
| M2 | 一次精确 owns 遍历内复用已解析 data | mutate | 原实际实例存在重复解析；局部指针不跨回调 | 已被编译器消除、需要持久缓存/跳过祖先检查 |

实施顺序 M1、L1 优先；R1、M2 独立机制审查后进入，不能为凑足四项实现。M1 新快路显式要求 `std::is_scalar_v<T> && !detail::future_custom_lifetime_supported<T>()`，包括 enum/scalar 的合法自定义策略也必须保留原调度。保留默认 scalar 的标准值初始化，不能全部 memset(0)，不能删除 resize 后 copy 所要求的初始化；fill/self-alias/custom 路径保留。

L1 的“未发布”不构成无重入证明：copy-load 在图验证前已经注册 registry，scratch upstream/new_handler 也能回调。必须逐项证明 owner identity、live storage、必要的 state/generation 与当前 address domain；保留 OwnerRecord 的 shared_ptr 不等于 pin 住 mapping。只在已证明不分配、不释放、不调用用户代码的局部区段复用 pointer；跨任何回调边界重新解析和核对当前 owner/存储。未建立优化证据或可选元数据不足时走原精确通路；一旦已检测owner退役、mapping失效或代际不符，按原契约安全拒绝，绝不能拿旧ctx.base/root继续fallback。无法闭合证明则否决候选，不缩小旧接口合法调用域。L1 不透明推广到 freeze、逃逸别名或未知 detail 入口；R1 不缓存跨调用的无 canonical 结论；M2 保持双向完整递归。

旧最小对齐、CheckedRange、透明 mutable locator、shared-control、cursor、allocation witness、bitmap/cell、scoped-specialized 的关闭决定不变。短 key 请求不是系统 malloc，不在本轮引入 SSO/共享 key/缩小 V1 header。
