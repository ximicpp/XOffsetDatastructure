# Automatic 相同轨迹与布局诊断（N5）

日期：2026-10-15。第二批实验以 F 的两个头文件为控制组，生产头保持不变。
96 个诊断样本和 2,016 个非插桩计时样本已完成并冻结；边界验证与离线审计通过。

## 决策

保留 F 的 Automatic 行为与默认 Explicit。已定位历史交错负载的 +6.60% 空间差异，
并实现、验证一个仅存在于生成头副本中的窄候选。候选能修复长寿命辅助容器的布局，
但会使部分短寿命辅助容器的空间和元素迁移增加；没有证据支持普遍替换 F。

## 相同操作轨迹

新增 `tools/bench_vm_automatic_trace.cpp` 和 `tools/run_vm_automatic_trace.py`。
每条确定性轨迹预先生成，分别在预分配、Explicit＋调用者重试、Automatic 下执行。
操作轨迹指纹、全部最终存活值、销毁前的临时容器值和 verified wire 往返必须一致。
参数独立控制初始容量、最大容量、主容器长度、插入节奏、辅助突发长度及辅助对象寿命。

本轮完整矩阵为：100 万个主元素，最大容量 32 MiB；初始容量 4/64 KiB；
每 256/1024 个主元素插入辅助元素；每次突发 1/8 个辅助元素；辅助容器持续存活或
每 16 个突发后销毁并以相同 allocator 重建，共 16 条轨迹、3 种执行方式。
预分配组在操作前将逻辑长度设为最大值；其初始化单独计时，不能把追加耗时解释为端到端成本。

正式计时使用原始头；诊断使用由精确匹配源码锚点生成的插桩副本。插桩记录 Core 新块、
复用、归还，wire 缓存命中、归还和整批转移，物理尾块检查、容量失败、增长，以及
`XVector<uint32_t>` 的实际元素迁移。日志提前预留，计时结束后输出。
诊断时间和含日志的进程 RSS 不用作性能比较。

迁移字节是本轨迹中实际执行元素构造迁移的 `size × sizeof(uint32_t)`，不包含内存清零、
页提交、框架或输出复制，不能称作进程总复制流量。Core 空闲字节包含分配头；wire 的
`free_bytes` 是缓存记录大小；另列从 Core 分配头读取的 wire 物理块大小，三者不可混加。

## 历史 +6.60% 的具体链条

精确历史条件为初始 4096 字节、每 256 次插入 1 个辅助元素、辅助容器持续存活。
Root 保留历史第三个未使用的 rows 字段，防止对象布局变化干扰对照。

| 指标 | Explicit | Automatic | 预分配 |
|---|---:|---:|---:|
| 最终 used_end | 4,235,792 | 4,515,392 | 6,999,152 |
| 调用者重试 | 11 | 0 | 0 |
| wire 缓存整批转移 | 10 | 3 | 0 |
| 元素迁移有效字节 | 57,344 | 319,488 | 2,809,856 |
| 最终主容器偏移 | 41,488 | 304,688 | 2,804,848 |
| 最终辅助容器偏移 | 8,560 | 4,499,008 | 699,472 |
| wire 记录空闲字节 | 8,192 | 15,360 | 16,384 |
| wire 对应物理用户块字节 | 8,192 | 304,128 | 707,264 |

事件中的操作编号从零开始，同时计入主、辅助插入。关键节点是：

1. 操作 16,449 后，偏移 8,560 的物理块有 32,768 字节，但辅助容器退还给 wire 缓存时
   只记录当时的 256 字节容量。它在 wire 层只能满足较小请求；转回 Core 后才能重新看见完整物理块。
2. 操作 32,896，Explicit 的主容器尾部扩展遇到逻辑容量边界，随后尝试新块分配、转移
   wire 缓存，抛出后由调用者 grow 并重试。Automatic 直接增长尾块，因此跳过这次缓存转移。
3. 下一次辅助插入（32,897）请求 1,024 字节。Explicit 在 Core 中复用偏移 8,560 的块；
   Automatic 的该块仍在 wire 小尺寸类中，于偏移 303,648 新建块，主容器随即失去物理尾部身份。
4. 操作 65,792，Automatic 的主容器必须迁移 262,144 字节到偏移 304,688；
   Explicit 继续在偏移 41,488 原地扩大。最终 Automatic 辅助容器还在尾端新分配 16,384 字节。

最终差额可以逐字节核对：主容器偏移多 263,200 字节，加上最后辅助块及分配头的
16,400 字节，共 **279,600 字节 / 4,235,792 = 6.6009%**。
两组最终逻辑长度都是 8 MiB；这不是地址预留量增加，也不是额外有效用户数据。

## 窄候选与反例

生成候选在确认有效物理尾块、Automatic、请求跨逻辑容量且未超硬上限后，
先调用内部回调转移 wire 缓存，再执行现有增长。回调沿现有 owner 查找传递，
不额外查询注册表、不新增公开策略、不改变 wire 结构。正式生产头未应用此候选。

候选将历史轨迹恢复到 Explicit 的 4,235,792 字节和 57,344 字节元素迁移。
对持续存活的辅助容器，16 轴矩阵中对应 8 条轨迹的 used_end 下降约 1.28%–26.40%。
但初始 64 KiB、节奏 256、每 16 波销毁辅助对象时出现反向结果：

| 辅助突发长度 | F used_end | 候选 used_end | 空间变化 | F 迁移字节 | 候选迁移字节 |
|---|---:|---:|---:|---:|---:|
| 1 | 4,202,864 | 4,268,496 | +1.56% | 19,920 | 85,456 |
| 8 | 4,205,248 | 4,402,944 | +4.70% | 131,376 | 327,984 |

提前转移改变了 wire 尺寸类复用与 Core 首适配整块复用的顺序；短寿命辅助对象的
原有复用链因此受损。仅为历史单条轨迹调换顺序会引入另一类浪费，故本轮不采用。
预分配也不是统一空间最优：没有边界触发的缓存转移，持续存活轨迹可能持有更大的旧物理块。

## 失败契约与适用建议

候选专用验证涵盖非空 wire 缓存下的 Enable/Prepare 失败、超最大容量不转移缓存、
缓存转移时宿主元数据分配失败、存活数据保持和后续 verified wire 往返。
既有 storage_policies 测试另覆盖嵌套构造后续失败、缓存先于增长、最大容量、move/swap。
缓存转移后才发生 OS 失败时，候选可能已改变空闲链表；不宣称分配器字节完全回滚。
宿主 OOM 仍只保证安全、无重复拥有权和析构不抛，不保证空闲容量守恒。

Automatic 的确定收益是消除调用者容量重试；布局取决于对象寿命和交错节奏。
有严格空间预算的使用者应按自身相同轨迹比较 Explicit、Automatic 和预分配，
同时看 used_end、逻辑长度、物理缓存和迁移，而不是只看总运行时间。
不建议为此增加多个公开增长策略，也不把自动增长描述为自动获得更紧凑的布局。

## 非插桩计时及边界

在 Apple M3 Pro、36 GiB、16 KiB 页上，使用固定 P2996 编译器和显式 SDK，
运行了三个连续协调窗口；其他阶段的构建暂停，桌面后台进程仍然存在。
每个窗口为 16 轨迹 × 3 执行方式 × 2 源码 × 7 次重复，共 672 个新进程样本。
这不是三个独立安静窗口，也没有相同二进制 A/A 对照；不同策略初始化方式已明确区分。

下面是 Automatic 操作循环中位毫秒（F → 候选）：

| 轨迹 | 窗口 1 | 窗口 2 | 窗口 3 |
|---|---:|---:|---:|
| 历史 4 KiB / 256 / 突发 1 / 持续存活 | 3.209 → 3.138 | 3.200 → 3.206 | 3.194 → 3.163 |
| 4 KiB / 1024 / 突发 1 / 持续存活 | 3.213 → 3.074 | 3.167 → 3.086 | 3.155 → 3.094 |
| 64 KiB / 256 / 突发 8 / 每 16 波重建 | 3.255 → 3.323 | 3.254 → 3.295 | 3.251 → 3.323 |

完整结果包含 Explicit 和预分配的控制组、配对比例及运行顺序分组。
7 次重复的配对顺序为 F 先运行 4 次、候选先运行 3 次；小幅差异只作描述，
不归因为某个源码分支，也不据此声称默认路径零回退。
本轮不采用候选的依据是可重复的精确空间/迁移反例，计时补充其实际代价。

循环时间包含 Explicit 失败重试、实际增长，以及有限寿命组销毁前各模式共同执行的
旧值检查；排除轨迹生成、arena 初始化、最终全部存活值和 wire 校验。
这与历史即时生成元素的 benchmark 计时范围不同，不能将新的约 3.2 ms 与旧报告约 4 ms
拼接为版本提速。所有 2,016 个计时样本的布局、容量、重试和语义均与相应诊断样本一致。
