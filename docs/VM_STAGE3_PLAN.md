## 2. 从当前实现出发的约束

- `XBufferCore::allocate_aligned_impl` 以 `free_blocks_` 的现有顺序首适配，整块返回；
  `deallocate_impl` 向宿主 vector 追加。物理头 `AllocationHeader` 为 16 字节，
  `total_bytes == 16 + user_bytes`；初次分配前的对齐空隙不属于该块，不能擅自回收。
- `try_expand_impl` 判断的是 `user_offset + physical user_bytes == used_end`。
  容器记录的容量可能小于物理块容量，不能通过缩短头部把存活尾块变成非尾块。
- wire 层在 payload 内保存尺寸类链表，`FreeBlockHeader` 为 8 字节。
  `block_bytes` 是退休时公布的容量，可能小于其背后的物理 `user_bytes`。
  `release_cached_blocks` 才把物理块转给 Core；两层不是同一张空闲表。
- Core 空闲元数据不随 wire 保存。load 后不能扫描未知字节猜测所有物理块，
  更不能把保存前的宿主索引强行恢复为完整分配图。
- 保持实际地址对齐，包含超过 OS 页大小的局部分配。V1 可序列化类型仍遵守既有
  对齐准入；超页对齐测试和 wire 兼容测试必须分开。
- 存活块、Core 空闲块、wire 空闲块必须唯一拥有每个物理区间。索引只是引用。
  `deallocate` 的宿主 OOM 仍为安全的尽力回收，不能宣称本阶段新增“释放永不分配”保证。
- 保留稳定 owner 基址、硬容量上限、Explicit 默认、清零、校验及失败契约。
  容器自己迁移仍可能使元素指针失效；后续构造失败也可能保留已增长的容量。

## 3. 候选与实验隔离

候选先生成到 `build/stage3-*/` 的独立快照，记录转换脚本或精确补丁及输入输出哈希。
生产头先保持 F。生成脚本必须检查每处源锚点的匹配数量并拒绝漂移；不将试验开关或
诊断接口永久泄漏进公开头。若采用后实现改变，维护当前 runner，历史 runner 和档案不改。

| 变体 | 唯一主要变化 | 对照 |
|---|---|---|
| F | 当前正式实现 | 所有候选的端到端基线 |
| A-core / A-wire | 首适配切分；物理尾 donor 保持整块 | F；另一层保持 F |
| B-core / B-wire | 与 A 相同的非尾策略；尾 donor 从高地址端分配 | 对应 A，另与 F 比较 |
| C-linear | Core 稳定槽位＋顺序记录，仍线性首适配、整块复用 | F，隔离元数据容器变化 |
| C-index | C-linear 相同 donor 规则＋尺寸桶/非空位图 | C-linear 隔离索引成本，再与 F 比较 |
| selected | 只组合独立通过的层/功能 | F 及各独立候选 |
| D-batch | 有证据才在已通过基线上增加触发式批量合并 | 同一基线且关闭合并 |

### A：首适配切分，保留物理尾 donor

1. 保留各层当前 donor 搜索规则：Core 检查 `user_bytes`、记录的 alignment 和实际地址；
   wire 按尺寸类/链表顺序检查 `block_bytes` 和实际地址，没有额外的 stored-alignment
   筛选。不把 Core 条件套给 wire，也不在同一实验中改为最佳适配或扩大匹配范围。
2. 用有效物理头判断 donor 的区间和尾部身份。物理末尾等于 `used_end` 时整块返回。
3. 非尾块只在能生成两个不相交、各自有合法 Core 头的分配区间时切分。
   前块保留原 user 地址；后块头和 user 地址均正确对齐，残余至少能表达其目标层空闲记录。
   对齐产生的间隙归入明确的块容量，或明确计为损失，不能凭空增加空闲容量。
4. 先完整计算边界、相对偏移、尺寸类和计数，再准备宿主元数据，最后无抛出发布。
   太小、不满足对齐或准备失败时，回退当前合法整块复用，不先破坏 donor。
5. Core 残余留在 Core，wire 残余留在同一个 wire state；实验中不额外触发缓存转移。
   新残余的插入位置需写入变体清单，建议 Core 占 donor 原槽位，wire 按既有类头插入；
   此规则与新增碎片一起属于切分候选，不误称与 F 布局完全相同。

wire 切分不能只把 `block_bytes` 分成两份：它必须拆分真实物理头，保证两个块未来
分别归还 Core 仍合法。先加入“wire 公布小容量、物理大容量”反例；物理尾余量明确归属
一个块，残余公布容量不得越过原公布边界，也不能在扣除新请求和新增头部/对齐成本后
凭隐藏余量扩充可用容量预算。若选择恢复隐藏余量，另立“切分＋余量恢复”变体和对照，
不能把它算作纯切分收益。首轮也不提高未切分缓存的公布容量。

### B：尾 donor 从高地址分配

仅改变 A 对物理尾 donor 的处理。设 donor 物理末尾为 E，请求为 R，按实际地址
从 E−R 向下对齐得到新 user 地址 U，新头在 U−16。新块的物理容量为 E−U，包含
必要尾部余量，从而仍是物理尾块；旧 user 地址处保留带原头的空闲前缀。

所有减法、地址溢出、头部对齐、前缀最小尺寸、相对偏移和尺寸类先验证。不合法时
保留 A 的整块尾 donor 行为。不能留下没有合法头的前缀，不能把邻接存活块或未知
对齐空隙吞入新块。重点比较“立即再增长”和“前缀先被其他对象使用再增长”两条轨迹。

B-wire 也继承 A 的公布容量预算。令原公布容量为 W、尾部对齐余量 P = E−U−R，
残余公布容量最多为 `min(prefix_physical_bytes, W−R−16−P)`，每次减法先检查下溢，
并保持原公布边界约束及最小缓存记录尺寸。不足则整块回退。不能仅取
`min(W, prefix_physical_bytes)`：U 可能落在原公布末尾之后，这会用隐藏余量完成新请求，
却不减少公布空闲量。若另行研究恢复余量，必须独立命名并设置对照。

### C：只优化查找，固定整块复用

首轮只改 Core；wire 已有尺寸类，保持 F。C-linear 使用稳定槽位，记录 F 的释放/插入
顺序并保留线性首适配，避免 vector 中间 erase 移动。C-index 在同一槽位结构上增加
尺寸桶、非空位图和可验证的槽位引用，两者必须选择同一 donor。

F 首适配是所有合格块中最早仍有效的插入项。按最小尺寸桶直接返回会改变规则；
严格对照应在合格桶中取顺序最早的可用项，实际对齐条件也保持一致。序号重用、
计数溢出和 move/swap/prune/load 生命周期都需要定义和测试。索引不能持有会失效的
vector 指针，不得以只看固定个候选后失败的方式漏掉可用块。无法快查时完整后备查找。

如果严格首适配消耗过高，可另立“索引＋选块策略”候选，但必须同时提供该新规则的
线性对照，单独预登记后才计时。不得将选择规则变化的空间收益全部归为索引收益。
新增元数据统计 capacity 实际占用、峰值、分配次数和操作成本；不承诺无条件 O(1)。
同规则对照逐请求校验 donor ID、偏移和最终布局；涉及超页对齐时，先控制两次实验基址
对最大对齐的余数相同，或在同一记录地址布局上重放选块，避免将 OS 基址差异误判为索引差异。

### D：有条件的延迟合并

只有 A/B/C 筛选完成，且已观察到可证明相邻的空闲块导致压力失败时才启动。
首轮在 Core 分配无法满足请求时做一次批量邻接合并，再重试；不在每次 free 全表合并。
如涉及 wire 缓存，先完成合法所有权转移；合并只包含当前 Core 唯一拥有且物理连续的区间。

临时排序/合并计划、索引空间和发布前检查先准备。准备失败保留原始结构并回到原有
失败/增长路径，不半合并。测试夹有存活块、未知对齐间隙、跨层邻接、重复触发和
合并后仍失败；量化合并耗时与额外宿主内存。若剩余碎片不支持此方向，记录条件不成立。

## 4. 正确性与故障验证

新增独立参考区间模型，不复制实现的链表/选块算法作为 oracle。模型记录申请 ID、
用户有效字节、物理区间、生命周期、所属层及已知损失，检查存活数据、不重叠、
唯一所有权、索引可达和计数。候选可以给出不同地址；除 C 的同规则对照外，不要求
候选与 F 选同一位置。固定容量压力可以完成不同请求数，不能将它们当成同工作量计时。
wire 层以可校验根对象驱动操作；save/load 后重新取得 owner、指针和 binding。不同策略
输出字节可能不同，比较逻辑值、结构校验和双向兼容，不要求原始 wire 哈希相同。

- 操作：allocate/free/expand、wire retire/flush、容器修改、save/load、grow/shrink、move/swap。
  load 后丢失的 Core 宿主空闲表按原契约建模，不误报为新泄漏；非法 double-free 不作为支持承诺。
- 分布：正序/逆序/随机/冷热释放，小块、大块、双峰、两波尺寸变更；Explicit、Automatic、预分配。
  对齐包含 1/2/8/16/64、运行时页大小和 2 倍页大小，并选取实际不满足超页对齐的基址。
- 边界：恰差一个 header 的残余、残余被占、物理容量大于公布容量、尾块多次复用、
  硬上限前后、接近整数上限但不实际申请巨大内存、save/load 后再分配/修改。
- 种子：先固定并保存 8 个种子，每条常规轨迹 10,000 操作；提交到常规测试的 smoke 可用
  2 个种子×1,000 操作。深度压力追加 32 个种子×100,000 操作，分批运行并记录实际完成量。
  失败保存完整轨迹并最小化，不通过重复重试掩盖失败。
- 真实宿主分配 fail-after-N 覆盖槽位增长、桶/第二索引、split 准备、转移、load 后懒建、
  合并临时存储。测试工具预分配日志/模型，故障只在被测操作周围启用，证明目标故障确实发生。
  正常成功路径和每个实际分配点分别覆盖；分开报告安全性和不能再复用的字节。
- 现有 OS Enable/Prepare 故障、嵌套构造失败、硬上限后不无限重试继续覆盖。
  必须保留“不静默重试 OS 失败”“先准备再发布”“策略随 owner 转移”等既有边界。

`tests/test_tail_expansion.cpp` 中 `physical_size_survives_core_reuse` 和
`physical_size_survives_cached_reuse` 包含 F 整块复用的具体大小/指针预期。B 有意改变
尾 donor 内的位置，应保留 F 测试，同时为候选分离策略预期和数据/对齐/尾块安全契约，
不能简单删除失败断言来获得通过。历史 `test_freelist_reuse.cpp` 仅在 E 档案中，
可提取反例，不当作当前已注册的 F 测试。

## 5. 性能实验与采用标准

正式计时前冻结工作负载、候选、指标、阈值和输入轨迹。诊断与计时使用不同二进制，
由同一候选源码生成；诊断数据不是正式时间证据。诊断包括 Core/wire 搜索和转移次数、
宿主分配/元数据移动/峰值、切分/整块回退原因、尾扩展结果、实际元素迁移字节及增长事件。
区分 used_end、逻辑长度、wire 长度、可访问页、RSS 和实际存活有效数据。

分三层测量，避免未经筛选就做全部笛卡尔积：

1. 微型筛选：Core-only、wire-only 的大块复用为小块、8/64/512/4096 个空闲项的查找、
   正序/逆序/随机释放、尾 donor 复用后增长、第二波压力。相同 trace 固定有效工作量。
   索引另覆盖同桶密集、尺寸合格但对齐不匹配、无适配项以及命中顺序头/尾，防止只测理想命中。
2. 集成守卫：历史 E 的三类碎片负载；N5 的 16 条交错轨迹（含短寿命反例）；
   默认首次/重复 save、verified load、顺序/交错 vector/string、嵌套容器、128 MiB grow
   及 1,000 万元素追加。池关闭为默认对照，另检查既有显式池不会改变采用结论。
3. 只有通过前两层的候选才做确认：同二进制 A/A、F/候选成对、每窗至少 8 对，
   AB/BA 数量相等，预热另记；至少三个独立运行窗口，保存顺序、进程活动、电源/热/交换状态。
   时间间隔本身不证明环境独立安静；噪声掩盖小差异时结论必须为不确定。

计时串行，不能与编译、sanitizer、另一基准并行。可并行分析/编写不同候选，执行子会话
统一调度测量。不停止用户无关进程。运行器要有超时、硬上限无进展检测、失败状态、
输入前后哈希及原始数据完整性检查；缺项、损坏或中断不能标记成功，`python -O` 亦有效。

采用预算沿用总计划，A/A 后、看到候选计时前锁定：

- 正确性、唯一所有权、稳定基址、硬上限、wire/签名兼容和适用平台验证是硬门槛。
- 简单时间优化目标至少约 5%；复杂索引至少约 10% 时间收益或 15% 有用空间收益。
  空间目标同时给出固定压力下成功请求/有效数据量，不能仅看 used_end 下降。
- 默认锚点新增耗时回退预算约 2%；可重复超过 5% 默认拒绝，2–5% 仅在预登记权衡
  满足时考虑。空间目标允许的耗时/宿主内存预算也须先写明，不能看到结果后放宽。
- 输出配对分布、执行顺序分层和区间估计；不以“不显著”证明等价，不用少量批次估计 p99。
  噪声、工具链或平台条件不足时保留 F，候选标“证据不足/前提未满足”，不虚构通过。

功能验证（明确 x86_64 仿真）、ASan/UBSan/LSan、受影响并发/生命周期 TSan、
历史 wire 两轮修改矩阵（包含 F 对照）、类型签名、full/storage 安装与多翻译单元消费。
按实际新增数量报告，不机械沿用 46/26/15。Windows 缺条件则保持未验证，不声称完整跨平台。
若关键验证不可用，则候选不进入最终已验证实现，保留 F 和明确的待验证候选。

若所有运行期候选被拒绝，验证新增测试/工具与 F 的组合，核对 F 两头未变，关联已有
不可变的完整验证证据；不把历史 sanitizer 结果说成本阶段重跑。

交付 `docs/VM_STAGE3_RESULTS.md`、本阶段独立 perf/validation 证据目录、候选决策表、
原始轨迹/样本/源码包/命令/工具链身份/审计脚本，并更新总任务清单。
决策状态至少区分：采用、拒绝、条件不成立、前提未满足。复杂实验未做不能写成完成通过。

## 7. 子会话执行与资源安排

创建一个项目内本地子会话作为唯一实施负责人，完整执行 S3.0–S3.5。它可以将只读
审查或隔离候选交给内部子代理，但生产头由一个负责人整合；A/B 与 C 的写入目录分离。
阶段 review 或候选拒绝不需要再次征求授权，继续推进其余已授权任务。最终发布、推送、
远端 CI 调度与本轮实现交接分开，不自动执行。

设计时磁盘剩余约 12 GiB：优先复用已验证工具链、依赖和 CMake bundle，先核对实际路径
与身份；不重建整套 LLVM 镜像，不复制整个历史 build 树。分批编译和归档，估算下一批
空间并保留余量；只清理由本阶段明确创建且已归档的可再生中间产物，不删历史证据或其他任务文件。

可用入口信息（子会话仍需核对）：本机 `/usr/local/bin/clang++`、
`/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`、`/usr/local/lib`；
Linux 工具链锁见 `toolchains/vm-validation.json`，已准备的 CMake 在
`build/stage2-cmake-verified/root`。不要把 clang++ 的符号链接改为 clang-21 驱动调用。

本文件只交付设计和执行边界，未声称 S3 实验已经运行或任何候选已获采用。
