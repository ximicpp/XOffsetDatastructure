## 安装包与持续验证

`XOffset::storage` 提供独立 C++17 OS 层；`XOffset::xoffset` 提供完整反射库。
顶层开发构建保留原测试，作为源码子项目时默认不构建 tests/tools/examples，也不插入安装规则。
完整包包括两个公开头、851 个固定依赖头、许可证及逐文件清单，共 860 个文件；
仅 storage 的包为 4 个文件。包不导出开发机的编译器、SDK、源码或标准库绝对路径。

完整目标传播 `cxx_std_26`，因此需要 CMake 3.30+；普通 storage 接口仍支持 CMake 3.13+。
固定编译器镜像内的 CMake 3.28.3 不满足新目标要求，所以新增独立的官方 CMake 4.2.3
输入，固定下载地址与 SHA-256。下载准备和离线验证分开；Linux 验证通过 `--cmake-root`
只读挂载完整工具分发包，记录文件哈希并在结束时复核。编译器镜像 digest 保持原值。

首次下载缺少尾部 10,746 字节，准备工具正确拒绝哈希不符的文件。补取官方响应中对应范围后，
完整文件大小 58,186,808、SHA-256 为
`5bb505d5e0cca0480a330f7f27ccf52c2b8b5214c5bba97df08899f5ef650c23`，
与官方校验清单及 GitHub asset digest 一致；只有这一份通过校验后用于解包和 Linux 执行。

CI 已接入 storage/full 安装消费验证、JUnit 上传和固定 CMake 准备；Dockerfile 配方使用同一锁。
`build.sh` 显式恢复 full/tests/tools/examples，防止重用精简消费配置时遗漏开发检查。
CI 修改已检查结构和本地等价流程，但没有远端运行记录；Dockerfile 未重新编译整套 Clang 镜像。

安装说明、语言要求和平台支持表见 [消费指南](VM_PACKAGING.md)。

## 性能与空间结论

N4 最终数据有 **987 个样本**：600 个矩阵样本（含 24 个同二进制 A/A）、144 个独立延迟、
192 个插桩、51 个生命周期样本。覆盖固定/混合/双峰/阶段容量、缓存 1/8/64/256、线程 1/2/4/8。
共享池和线程局部池的总空闲预算相同。稳定容量重复使用仍明显受益，8 线程共享池有锁竞争；
旧容量占满缓存后，容量阶段切换会持续未命中，索引不能解决保留策略问题。
短空闲实验仍显示回收节省 RSS、再次触页更慢，保留显式选择。

这些是 OS 层合成筛选结果。桌面及其他容器活动仍在，不能据此定位几个百分点的默认路径回退。
早期调度不平衡的 pilot 已排除并原样保存；最终数据重新采样，RSS 生命周期差异亦已注明。
详见 [池与回收报告](VM_POOL_WORKLOAD_RESULTS.md)。

N5 完成 **96 个诊断样本和 2,016 个非插桩计时样本**。历史额外 279,600 字节的分配链已逐事件核对：
Automatic 避开一次 wire→Core 缓存转移，旧大物理块滞留在 wire 的小容量记录中，
辅助容器新块抢占尾部，主容器随后多迁移一次。提前转移候选改善长寿命布局，却破坏部分短寿命复用链。
采用决定依据精确空间和迁移反例，连续三个计时窗口仅作代价描述，不是安静主机上的独立确认。
详见 [Automatic 轨迹报告](VM_AUTOMATIC_TRACE_RESULTS.md)。

独立 review 还修复了测量工具的硬上限重试死循环、子进程超时、输入清单身份复核及失败记录。
这些维护修正不修改既有测量档案；归档明确区分冻结实验版本与当前维护入口。
