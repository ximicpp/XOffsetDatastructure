## 基线与不变边界

第 3 阶段六候选均拒绝，正式版本仍为 F；详见 [第 3 阶段结果](VM_STAGE3_RESULTS.md)。
网络实验启动时重新冻结源码、依赖、工具链、输入和运行器。基线双头 SHA-256：

```text
xoffsetdatastructure.hpp
9bc8f1f533bee83a9e111e05d67319383775dbca1844ef33b1aa717047640bb2
xoffset_virtual_memory.hpp
22f181b52c11ce442a5576ffc0dc35af1828f77deb4424f387d0acfa658239ad
```

使用现有 V1 wire；不新增稀疏 wire、分段协议、消息封装字段或公共 I/O API。
传输适配器可以把同一报文分多次读写，这是处理传输进度，不改变报文字节。
不得把借出的 `bytes()`/`get_buffer()` span 直接用作发送报文。

当前 F 的相关事实如下，均来自 [生产头](../xoffsetdatastructure.hpp) 与
[生命周期说明](STABLE_VM_STORAGE_MIGRATION.md)：

| 接口 | 当前行为 | 网络消费者约束 |
|---|---|---|
| `load_verified<T>(string/span, cap)` | 检查 V1 头后，把 payload 复制到新 owner；验证根、分配器及完整结构图后才允许 typed root 访问 | 输入必须稳定至调用返回；成功后 owner 独立拥有数据，失败不发布新 root |
| `save_verified<T>()` | 先按 used_end 缩小逻辑长度，再生成拥有型 string，包含 V1 头和完整 payload | 保存会修改逻辑长度，调用期间需独占 owner；返回后输出 string 独立于 owner |
| `bytes()` / `get_buffer()` | 借出当前逻辑 arena payload，不含 V1 头，不是快照，也不保证已规范化 | 不能替代 verified 保存，也不能只延长 span 对象寿命就保证底层有效 |
| `MaximumCapacity::with_pool` | 显式选择池；池按精确最大容量复用空闲映射 | 新加载仍复制和校验；对照必须包括当前池化加载 |
| move/swap/handle | move/swap 改变 C++ 对象对应存储并推进 epoch；handle 跟随原 C++ 对象 | 不把 handle 当作共享所有权；异步工作持有真实拥有对象 |

稳定 arena 基址不保证容器元素永不迁移，也不提供并发修改安全。`save_verified` 输出
已经独立拥有数据，网络发送不需要继续借用原 owner；若业务仍使用 owner，其生命周期
由业务显式管理。池只限制空闲映射，不限制存活 owner 或在途网络缓冲。

## 最小参考流程

第一版网络功能消费者保留当前的两次拥有型复制，复用文件消费者的确定性 schema、
输入与数据处理；请求及响应都使用原有 V1 报文。默认流程为：

```text
接收完整且有界的 V1 报文至 owning string
  → load_verified 创建并完整校验一个新 owner
  → 仅成功后进入相同的确定性处理
  → save_verified 生成 owning string
  → 按进度发送完整字符串
  → 接收端完整读取、verified load、逐值核验
```

这只是实验请求/响应，不添加生产协议的请求 ID、ACK、重试或业务消息语义。
首个功能参考可把在途请求限制为一个，以明确缓冲与所有权；该限制属于合成实验条件，
不决定生产并发设计。未来可在本机有界 loopback 上建立传输对照，但不能把 loopback
吞吐、时延或复制占比外推到远端链路、TLS、其他网络库或实际业务。

如果实际传输已有消息边界，沿用它的完整消息长度并核对 V1 长度。若后续实验采用 TCP
字节流，V1 自身的固定头及 `used_bytes` 可以界定现有报文：读取恰好
`sizeof(XWireHeaderV1)` 字节，验证后读取恰好 `used_bytes` 字节，不再增加长度前缀。
一次读取可能只返回部分字节，多条报文也可能连续到达；解析器按剩余长度推进，不能
把一次收取等同于一条完整消息，不能把后续报文误算成首帧尾部。

V1 头按原格式解释，不私自改成新的网络字节序。固定头先复制到对齐的本地对象，
核对 magic、版本、头长、endian、flags、schema、保留字段及 offset/length 基本关系。
确认受支持的 endian 后才能依赖长度数值；先检查 `used_bytes <= MAX_PAYLOAD`、
`used_bytes <= owner_capacity` 及 `used_bytes <= max_wire_bytes - sizeof(header)`，
减法前检查 `max_wire_bytes >= sizeof(header)`，然后才分配整个接收缓冲。
不能根据未验证的长度直接分配，也不依赖读取到 EOF 来判断帧完成。

`max_wire_bytes` 限制整个报文，`owner_capacity` 限制 payload 及后续处理所需增长空间，
二者单独命名、冻结并记录；不能把传输长度、arena 逻辑大小和预留上限混为一项。
传输侧头部检查只用于边界与资源准入，不替代最终 `load_verified` 的完整结构校验。
它接受的头条件必须与当前 F 兼容，包括既有合法 `reserved_bytes` 表示；不把本轮
发送端的规范化输出误当作唯一可接受的历史输入。

## 所有权、发布与取消

接收上下文持有 header、owning 输入、实际进度、限额和终止状态；发送上下文持有
owning 输出及偏移。同步返回、异步回调或等待状态由未来适配器实现，公共状态模型
先与具体网络库分离。第一版不将输入直接写入现有 owner，也不在半帧到达时访问 root。

完整报文交给 `load_verified` 得到临时新 owner，只有校验成功且操作未取消时才交给
处理方。若将来业务要替换旧 owner，应先完成新 owner 的校验，再在单一同步点发布；
这属于调用方的 staging 方案，不是已有的 `load_into` API。失败保留旧 owner，但成功
替换会改变旧引用/handle 的含义，不能借此承诺旧引用继续有效。

异步输入在接收完成或取消完成前不得释放、扩容或被其他线程改写；输出在网络库明确
报告不再访问缓冲之前保持有效且内容不变。发起取消不等于取消已经完成，不能立即
释放缓冲。完成回调只能终结操作一次；取消后的迟到回调不得重新发布 owner 或结果。
以网络库的实际 completion 契约实现这些规则，不能先假定某个库的取消行为。

正数短读/短写只更新进度并继续；零进度、暂不可用、EOF、超时和错误分别表示，避免
零进度忙循环。重试只处理适配器定义为可恢复的条件，不自动重发一条部分发送的业务
消息。已经写入连接的字节无法撤回；发送成功也只代表对应传输 API 的完成条件，
不直接等于对端已接收、验证或业务处理完成。

自有实验连接遇到半帧取消、截断、坏头或不可恢复错误时，可以终止连接来避免残余
字节污染下一帧；不扫描 magic 猜测重新同步。生产连接能否丢帧、排空剩余字节、重用
连接或重试，需按未来协议和业务契约另定。协议未知时不声称具备恢复能力。

背压须限制在途条数、在途总字节、单帧上限和待发队列，不仅限制池空闲量。
达到预算时暂停继续接收/提交工作；连接关闭后释放自有资源。异步适配器还须明确
超时、取消与读写完成的竞态，以及缓冲真正可释放的时点。

## 功能与失败矩阵

网络实现开始前冻结以下检查集合；使用可控适配器注入与真实 loopback 运行分别记录，
不把模拟回调等同于真实网络库行为。

| 类别 | 至少覆盖 |
|---|---|
| 帧边界 | header 每个切分点、payload 的预登记代表性边界处分块；多帧连续输入；恰好完整帧后关闭；帧头/帧体中途 EOF |
| 长度与格式 | 短头、坏 magic/version/endian/schema、溢出长度、单帧超预算、头与实际长度不一致；完整但结构图非法 |
| 进度 | 正数短读写；零进度；暂不可用后恢复；重复唤醒；部分传输后错误；不无限循环 |
| 生命周期 | load 失败不发布；处理失败不发送成功结果；发送缓冲持有到真正完成；owner 先释放时 owning 输出仍有效 |
| 取消与断连 | 头前/头中/体中/校验前/发送前/发送中取消；对端中途关闭；迟到完成；部分发送不重发整帧 |
| 背压 | 单帧上限、在途总字节、队列上限；慢读端；预算恢复后继续；终止后资源归还 |
| 池 | none/cold/warm 逻辑结果相同、硬上限相同；命中/未命中可解释；清池不破坏在途 owner；失败后再次加载完整覆盖可见数据 |

完整功能验收需要选定的适配器和明确的截止时间，但不需要业务消息分布已知。
同步与异步模式若都实现，各自证明其生命周期和失败条件，不用同步通过代替异步通过。

## 分阶段实施与启动条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| 当前：文件对照 | 完成已经启动的 F 文件完整流程测量与独立诊断，保留 none/cold/warm | 冻结输入、A/A、执行环境、计时边界及原始数据齐全；结果仅属于文件参考 |
| 网络功能消费者 | 实现与库无关的有界帧状态模型，再接一个明确标为实验用途的 loopback 适配器 | 上述功能/失败矩阵通过；V1 字节和逐值语义不变；未新增生产 API |
| 网络独立测量 | 冻结实验适配器、连接生命周期、负载和缓冲预算；串行测量与单独诊断 | A/A 校准、相同工作量、完整配对记录、环境与缓冲成本可追溯；不外推到业务 |
| 有条件的生产候选 | 有端到端成本证据后，分别设计 owner 复用、直接 staging 读取或减少输出复制 | 每项有明确失败/寿命契约、收益预算和 F 池化对照；未满足则不新增 API |

无业务尺寸时，网络合成对照沿用文件的 4 KiB、64 KiB、1 MiB、16 MiB 名义尺寸，
并记录实际 wire 长度、元素数和 owner 上限。这四点不是业务分布，不推断最大生产
消息或消息占比。测量开始前为实验冻结有限运行次数、超时和内存总预算；不是把
“参数未定”当成无限尺寸、无限连接或无限排队的许可。

测量至少区分：发送方提交到传输完成、接收方完整帧到 verified load/处理/保存、以及
请求到完整响应的往返；不同边界分别命名。先有正确语义再定义主指标。端到端计时
不插入逐阶段探针；独立诊断记录读取、复制加载、校验、处理、保存复制、发送及释放。
输入/输出析构、连接建立、pool 清理、语义检查和预热是否计入都须明确。

比较 none/cold/warm 时保持同一连接行为、输入、处理、校验和硬上限；cold/warm
只描述 owner 池，不表示冷/暖网络。空闲池总预算相同，实际在途 owner 另计。
不要靠复用连接、增大队列或减少验证来制造池收益。候选 `load_into` 的对照必须
含 F 的池化加载，因为池已经减少映射成本而未改变拥有/校验语义。

## 已完成的研究与仍待明确的事项

文件对照、相同 V1 fixture、帧状态与所有权、失败矩阵、有界同步 TCP 回环参考、
独立诊断和有限测量均已交付。原始数据完整不等于测量噪声合格；既有失败尺寸和
池对照不追加重试，也不启动缺少解释性收益及寿命契约的生产候选。结果仅属于
已冻结的参考配置。异步生命周期模型不能代替某个生产异步 transport 的实测。

生产协议/网络库、同步或异步完成契约、业务 schema 和真实尺寸分布、连接复用/并发、
TLS/压缩、延迟/吞吐目标及失败恢复要求仍未确定。这些信息不是当前基础研究的阻断项，
但在生产整合和 API 采用之前必须有明确契约与代表性证据。若仍未知，就交付研究
结果与限制，不把合成收益标为生产收益，也不关闭 N7 或整体路线图。
