# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

XOffsetDatastructure is a zero-encoding/zero-decoding serialization library: objects live inside a contiguous buffer and use offset pointers instead of raw pointers, so the raw bytes *are* the serialized form. The whole library is the single header `xoffsetdatastructure2.hpp` (C++20, Boost.Interprocess/Container/PFR). `main` is the Boost.PFR ("practical") line; `release/v2.0-cpp26` is an experimental variant using C++26 `std::meta` reflection.

## Build and test

Boost is a git submodule (`external/boost`) used header-only via explicit include paths in the root `CMakeLists.txt`; run `git submodule update --init --recursive` first. Schema code generation needs Python 3 with PyYAML.

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure        # all tests
ctest --test-dir build -R TypeSignature -V        # one test by CTest name
./build/bin/test_vector                           # or run a test binary directly
./build/bin/demo
./build.sh                                        # configure + build + run a subset of tests + demo
```

- Every test is a standalone executable (`tests/test_*.cpp`, each with its own `main`) output to `build/bin/` (`build/bin/<Config>/` on MSVC). CTest names differ from binary names (e.g. `MemoryStats` → `test_compaction`); see `tests/CMakeLists.txt`. A new test must be added there as `add_executable` + `add_test`. `tests/run_all_tests.cpp` is not built.
- CI (`.github/workflows/ci.yml`: macOS, Linux GCC 11/Clang 14, Windows MSVC, Android, iOS) pre-generates headers and configures with `-DSKIP_SCHEMA_GENERATION=ON`.
- `-DOFFSET_DATA_STRUCTURE_2_CUSTOM_CONTAINER_GROWTH_FACTOR=0` switches containers to Boost's default growth; the default (1) uses a 1.1x growth factor to keep buffers compact. `XOFFSET_DISABLE_PLATFORM_CHECKS` disables the 64-bit/little-endian `#error`s.

## Architecture

### Core header (`xoffsetdatastructure2.hpp`)
- **`XTypeSignature`**: builds a compile-time string describing a type's exact binary layout (sizes, alignments, field offsets, optionally field names via a static `_field_names` member) using Boost.PFR. Equal signatures across compilers/platforms mean buffers are binary-compatible. `BASIC_ALIGNMENT` (8) is the required `alignas` for all stored structs.
- **Boost.Interprocess extensions**: `XManagedMemory` is a managed-memory segment backed by an in-process `std::vector<char>` that can `grow()` and shrink; allocation uses `x_seq_fit`.
- **`XOffsetDatastructure2` namespace**: `XString`, `XVector<T>`, `XSet<T>` (flat_set), `XMap<K,V>` (flat_map) are Boost containers with segment-manager allocators. `XBuffer` is the user API: `make_root<T>(name)`, `find_root<T>`, `find_or_make_root<T>`, `create<T>(...)` (injects the allocator), `allocator<T>()`, `save_to_string()` / `load_from_string()`, `stats()`.
- **`is_xbuffer_safe<T>`**: C++20 concepts that recursively reject pointers, references, polymorphic types, unions, and `std::` containers/strings. The container concepts detect X-containers structurally (size 32, align 8).
- `XBufferCompactor::compact` is a stub that `static_assert`s; compaction is not implemented on this branch.

### Schema → generated code pipeline
Types stored in a buffer are normally defined in `schemas/*.xds.yaml` and generated by `tools/xds_generator.py <schema> -o generated/` into `generated/<name>.hpp`. Each type produces:
1. A **runtime type** (non-aggregate, has allocator-taking constructors) used for storage.
2. A **`<Name>ReflectionHint`** aggregate with identical layout, so Boost.PFR can reflect it.
3. `static_assert`s checking safety, matching size/alignment between the two, and that `get_XTypeSignature<…ReflectionHint>()` equals a **signature string precomputed in Python**.

Consequences:
- The Python generator reimplements the C++ size/alignment/offset and signature-format logic. Any change to `TypeSignature` output in the header must be mirrored in `xds_generator.py` (and vice versa), or every generated header fails to compile.
- `generated/` is committed and CMake writes into the source tree (not `build/`). After editing a schema or the generator, regenerate and commit the headers. A new schema must also be added to both `SCHEMA_FILES` and `EXPECTED_HEADERS` in the root `CMakeLists.txt`.
- Only `test_basic_types`, `test_msvc_compat`, and the examples include generated headers; most other tests define their structs inline with the same pattern (allocator constructor + `alignas(BASIC_ALIGNMENT)`).

`schemas/README.md` and `tests/README.md` are partly outdated (e.g. `XBufferExt`/`make`, generated output in `build/generated/`); trust the code over them.
