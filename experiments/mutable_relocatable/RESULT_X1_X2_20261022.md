# X1 重定位税 + X2 同进程整块复制：云端结果

2026-10-22 · 「可修改可重定位定位」线程 · 分支 `claude/mutable-relocatable-positioning`

**口径**：云端 Firecracker 虚拟机（Intel Xeon 2.10 GHz，4 核，Linux 6.18.44），官方 `gcc:16` 镜像（GCC 16.2.0，`-std=c++26 -freflection -O3 -DNDEBUG`），绑在 2 号核上。每格是 201 次配对重复的中位数，std 和 XOffset 交替跑。比值 = XOffset ÷ std，越小越好；p10、p90 是逐次比值的分位数。两轮（`out_x1x2_run1.txt`、`out_x1x2_run2.txt`）结论一致，下表取第 1 轮，括号里是第 2 轮。**这台机器只能看比例和量级**；要引用的数字按 `PERF_GOAL.md` 的口径在 Mac 上测。P2996 Clang 一侧没测（云端编不了）。

程序：`reloc_tax.cpp`；构建和运行：`build.sh`。SLG 部分直接用 `bench/slg/include/slg/` 里的模型和游戏逻辑（std 模型和 XOffset 模型跑同一份模板代码），只跑内存里的操作，没有任何编码、解码、收发。XOffset 一侧的设置和 SLG runner 相同：Automatic 增长、256 MiB 上限、VM 存储。

## 1. 结论

1. **重定位税不均匀。** 读（遍历、下标、查询）和整段搬移（中间插入删除、批量删除、map 删除）已经和 std 持平或更快；税集中在几条写路径上：
   - `push_back` 2.0 倍（2.6），从空开始还要加 reset，3.3 倍（3.5）。
   - 短字符串赋值 2.9 倍（2.2），长字符串 1.5 倍（1.6）。
   - `reset<T>()` 一个 16 KiB 的 buffer 146 ns，std 新建一个空消息 33 ns，4.4 倍（4.6）。
   - 元素带字符串和向量的 `XVector<Hero>` 中间删除 1.60 倍（1.60）。
   - XMap 查找对 `std::flat_map` 2.1 倍（1.9），对 `std::map` 1.19 倍（1.18）。
2. **SLG 逻辑原地跑：** simulate 1.13 倍（1.11）、season_edits 1.13 倍（1.13）、apply 稳态 1.38 倍（1.38）、ticks 0.95 倍（0.99）、query 1.02 倍（1.02）。和 Mac 上 A 对 zpp_bits 的阶段拆分方向一致（apply、simulate、req_encode 慢）。A.build_msg 2.1 倍（2.1），其中大头是 reset。
3. **每个 arena 第一次释放块时要建空闲表。** apply 的第一遍（每个玩家第一次被改）中位数 1.56 倍，但 p90 是 15 倍：空闲表约 12 KiB，线程缓存只留 4 张，新建时在这台虚拟机上要几 µs 到十几 µs。只发生一次，稳态不受影响。
4. **同进程整块复制是 XOffset 的强项，前提是有 `clone_into()`。** 复用目的地时：
   - 玩家（payload 11.5 KB，22 个空洞）：380 ns，std 拷贝赋值 1,567 ns，**0.24 倍（0.26）**。
   - 地图分片（payload 890 KB，1,497 个空洞）：65 µs，std 180 µs，**0.36 倍（0.36）**。
   - 两者都接近 memcpy 下限（215 ns、64 µs），多出来的是复制空闲表。
5. **现有 API 做不到这一点。** 同样的复制，今天只能 save + load_unverified（1.8 倍、1.2 倍，而且丢掉空闲表和类型化访问），或者 save_verified_into + reload_verified（2.3 倍、1.6 倍，含校验）。`clone_into()` 比后者快约 10 倍（玩家）和 5 倍（分片）。
6. **`clone()` 新建 owner 时和 std 拷贝构造打平（1.20、1.01 倍）**，开销在新建 VM 预留上（这台机器上一次几 µs）。R1 的槽位存储落地后，小 buffer 的这部分会降到池化级。

## 4. X2 同进程整块复制（ns/次）

参照列：拷贝构造（新对象）对应"新建 owner"的几行；拷贝赋值（目的地已有一份同形状的副本，std 的最好情况）对应"复用目的地"的几行。

| 对象 | 做法 | std | XOffset | 比值 |
| --- | --- | ---: | ---: | ---: |
| 玩家 11.5 KB | memcpy 下限（对拷贝赋值） | 1,512 | 215 | 0.14 |
| | save + load_unverified（对拷贝构造） | 6,295 | 11,235 | 1.79 |
| | save_verified_into + reload_verified（对拷贝赋值） | 1,649 | 3,782 | 2.29 |
| | `clone()` 新建 owner（对拷贝构造） | 7,404 | 8,865 | 1.20 |
| | **`clone_into()` 复用目的地（对拷贝赋值）** | 1,567 | **380** | **0.24** |
| 分片 890 KB | memcpy 下限 | 191,712 | 63,589 | 0.33 |
| | save + load_unverified | 329,368 | 395,001 | 1.20 |
| | save_verified_into + reload_verified | 208,216 | 335,723 | 1.61 |
| | `clone()` 新建 owner | 339,368 | 342,179 | 1.01 |
| | **`clone_into()` 复用目的地** | 179,865 | **65,479** | **0.36** |

正确性检查（程序里，两轮都过）：
- 克隆和源的内容摘要相同，空闲块个数和字节数相同，空闲表完整性相同。
- 两边 `save_verified` 出来的 wire 逐字节相同；克隆的 wire 能 `load_verified`，内容不变。
- 改克隆不影响源；克隆接着改的结果和 std 副本做同样修改的结果一致。

## 5. `clone()` / `clone_into()` 原型

只在本分支的 `xoffsetdatastructure.hpp` 里，没有进 next_cpp26：
- `XBufferCore::clone_state_from(src)`：把源的 `used_end` 字节复制进本 owner 的存储（走 `reinit_from_bytes`，epoch 加一）；空闲表完整时逐个非空 bin 复制过来；类型化访问、schema 绑定、根类型标识照搬。
- `XBuffer::clone()`：新建一个 owner（上限和增长策略同源），再 `clone_state_from`。
- `XBuffer::clone_into(dst)`：复用 dst 的存储。
- 不做校验，理由是源是本进程里活着的 buffer（边界矩阵 B1，O3–O5、O7 白送）。

没做的：对 R1 槽位存储的适配（I1 落地后要重看）；带池的源（新 owner 现在不带池）；P2996 Clang 构建和全量 CTest。

## 6. 交给「性能优化」的线索

都是推断，要在 Mac 上确认：
1. `push_back` 快路径：clear 后容量够时仍是 std 的 2 倍。
2. 短字符串内联赋值：8 B 仍是 std 的 2–3 倍，看 `ensure_bound()` 和 `arena()` 的开销。
3. `reset<T>()`：146 ns，主要应是按旧的逻辑长度清零（和已排期的 N2"只记脏区间"是同一件事）。
4. XMap 查找：对 `std::flat_map` 2 倍，考虑键单独成列或无分支二分。
5. 元素带容器头的中间删除：1.6 倍，rebase 每个被搬的嵌套头。
6. 每个 arena 第一次释放时新建空闲表：一次性，但在多 buffer 场景（每个玩家一个 buffer）里每个都要付一次。

## 7. 后续更正（10-22 21:46Z，「性能优化」转来「容器操作提速」的结论）

- **XMap 查找 2 倍是假象。** 本程序每轮复用同一批键，「容器操作提速」查明这是测量假象。键每轮换新、并且有了 #51（无分支二分）之后，查找 ÷ `std::flat_map` 为 0.16。第 1 节第 1 条、第 2 节"map 查找"一行和第 6 节第 4 条以此为准。
- **Hero 中间删除 1.60 倍是没声明普通记录时的数字。** 本程序没有给 `Hero` 等记录类型声明普通记录（`wire_record_layout<T>::ordinary_members`，#55 的 `XOFFSET_ORDINARY_RECORDS`），走的是逐元素搬移；声明后是 std 的 0.74 倍。第 6 节第 5 条以此为准。
- 这两组测量由「门禁基准入库」入库为 `bench/reloc`（键每轮换新），指标是 `PERF_GOAL.md` 的 G9（重定位税）和 G10（clone ÷ std 深拷贝）。
