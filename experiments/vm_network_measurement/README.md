# W3 measurement and portable evidence

`paired_measurement.py` supplies strict JSON/report validation, balanced paired
schedules, reclamation accounting and read-only portable audits. Its standalone
native evidence mode is disabled. Synthetic tests establish tooling behavior,
not native performance or adoption.

`default_measurement.py` and `default-contract.json` implement the separate
historical D/F bridge. The accepted queue compiled both frozen sources and ran
six functional processes. The one approved 78-process F/F calibration completed,
but all four metrics failed the preregistered 1% small-difference gates. No retry,
D/F comparison or ablation ran. Final evidence and limits are in
`docs/perf/vm-default-attribution/RESULTS.md`; that line has no further timing
authorization. Its frozen protocol and evidence remain immutable.

`network_measurement.py` binds the parent-accepted W1 revision2 contract and G1
timing producer. It retains complete input/output bytes, raw stdout/stderr and
receipts, and validates exact native work, schema, source/toolchain/dependencies,
resource bounds and one active W4 queue lease. Native collection requires a
separate externally pinned parent approval. The interpreter's absolute/resolved
paths, bytes, size and version are pinned for the new timing window.

Eight bounded native functional calls already generated the four deterministic
fixtures and canonical outputs under the c53 preparation protocol. A hardened
supplementary offline audit preserves those executed source bytes, checks all
eight ordered intervals and their completed functional queue, and distinguishes
execution from auditor provenance. Historical Python bytes/version were not
recorded; no current identity is substituted for that missing fact. This does
not relax the interpreter pin required for new timing.

`bind_network_window.py` creates one complete **proposal**, with full fixture
proof, accepted W1 build and smoke evidence, contracts, frozen protocol/runtime,
canonical data, exact schedule and invocations. It never runs a producer or
writes an approval. The concrete calibration has 112 pure F/F calls: four sizes,
two warmup pairs and four A/A pairs at each pre/mid/post anchor. Both documentary
endpoints use F with pool none. There is no cold/warm treatment, automatic
comparison or retry. The generic unbound template still contains the two future
pool comparisons and must not be used as the bound calibration schedule.

All C++, diagnostics, formal timing and substantial archive I/O use the accepted
`experiments/vm_coordination/run_job.py` queue. One timing lease covers the whole
approved calibration. After its supervisor exits, the completed sibling queue
receipts are copied into the window before sealing/auditing. Native audit uses
only retained bytes and treats original absolute paths as descriptions.

The adjusted network metric adds only recorded nonoverlapping cold/final clear,
client owner release and residual server completion wait to the measured RTT.
String destruction, worker creation/final join and other declared exclusions
remain unmeasured; full lifecycle cost is unavailable. Iterations within one
process are operation samples, not independent windows or production p99.

The three candidate directions remain prerequisite-unmet. Static feasibility
notes do not authorize an implementation; cost evidence, a selected complete
transaction/completion/resource contract and a parent decision are still needed.
See `docs/VM_IO_CANDIDATE_DECISIONS.md` and `handoff.json` for current status.

The one approved 112-process native calibration has now completed and passed

Full byte audit and independent small-record recomputation passed; portable
